# 部门公共成本与IT净亏损分摊

## 已确认的业务规则

- 运营部、商务部、AI视频内容部属于业务部门，人员成本归项目，不以未分配的月人员成本余额作为公共成本来源。它们的业务项目可以接收公共成本分摊。2026年9月起，人员月成本必须全部进入本人参与的项目：现有投入比例是相对权重，计算时归一到100%，不改写原投入版本。
- IT部不承担日常公共费用，也不接收公共支持成本。IT人员成本已经包含在IT项目经营结果中，不再单独加入公共人员成本池。
- 同一公司、月份、币种下，IT项目盈利先抵扣亏损；仅将剩余净亏损分摊给业务项目。盈利大于等于亏损时，该部分分摊金额为零。
- 其他部门的公共人员成本仍按既有来源、项目直接承担金额及历史关联支出扣除口径计算，与IT净亏损组成公共支持成本池。2026-09-30确认：在“分摊给负责人”一步，将该池与日常公共费用相加，只设置一套负责人比例，并下发一笔合并任务。
- 页面保留运营部、商务部、AI视频内容部及其他部门的人员成本和项目承担明细；三个业务部门的待分摊金额为零。IT仅在人员明细下方显示抵扣后的待分配金额。展示明细不扩大公共成本来源；盈利部门缺有效月成本、项目比例或存在待确认、无法完整分配时阻止新分摊，不能将未分配余额默认为零。

```text
IT待分摊净亏损 = max(0, -sum(IT项目当月转分前经营结果))
公共支持成本池 = 其他部门公共人员成本 + IT待分摊净亏损
公司项目成本变化 = 业务项目转入的IT亏损 - IT来源项目转出金额 = 0
```

IT使用已有日结果的税前经营口径：收入减业务成本、内部人员成本、奖金、已计入公共费用，加核算调整。统计有效项目，与现有公司经营汇总范围一致；已删除项目的历史结果不改写，也不重新加入新分摊来源。月份期间采用实际日期优先、计划日期回退；历史项目没有显式部门时沿用现有核算的负责人部门回退规则。

## 办理与核算

- 保留公司公共费用的三步流程和两级比例。新增来源快照标记为 `DEPARTMENT_NET_V1`；负责人只能分摊给同公司、同币种的本人业务项目。候选部门、负责人、项目均排除IT及其下级，后端保存与提交再次检查项目属性。
- 当月显示截至当天的已核算盈亏，不能视为完整整月金额。缺日结果、待计价、未确认收支、计划工作未确认，以及自动人员成本与已有日结果不一致时，金额为未知并阻止保存。
- 亏损来源项目必须能够记入转出；未结算的转分未完成时不能关账。盈利项目抵扣后，剩余净亏损按亏损来源金额分配转出额度，保存来源项目和额度快照。
- 新公共支持分摊按承担项目期间的自然日计入；IT转出跟随业务项目转入的日期逐日记录。每日和整月金额守恒、分币尾差稳定，负责人只提交部分时也只转出对应份额。其他公共人员成本不会从IT项目抵减。
- 日表的 `it_transfer_amount` 单独保存转出额，`amount` 为最终公共成本净额。IT侧的转出显示为成本抵减，不增加公司收入；重新计算IT来源盈亏时剥离该转出，防止分摊一次后亏损来源自动变小。
- 退回同时撤销业务项目转入和IT转出；重复同步不会再次扣减。月结确认既有日明细；已关账来源保存原记录。已结算IT和人员来源封存，通用“登记调整”仅调整日常公共费用，不能借此增加或删除不配对的IT转分。
- 原 `AUTOMATIC` 及人工快照保留原校验和日暂估口径，已下发或已结算金额不自动改写。人员投入比例、人员费率、真实账单及原项目事实不由本次代码修改自动调整。

## 盈利部门整月人员成本补充规则

- 仅在本人有效参与的项目间分配。单项目20%归一为100%；两个项目20%、30%归一为40%、60%。原投入比例保留为来源数据。
- 当月完整人员成本先确定，按整月有效参与工作日期及当日项目相对权重确定每个项目的月度金额，再将项目金额按有效日期分到每天；月中项目开始或结束不丢失月成本。分币尾差按项目累计分配处理，禁止负尾差，整月合计等于月成本。
- 项目期间、成员加入/退出、观察员身份、暂停和参与计划仍决定有效日期。没有有效项目或比例合计为零、比例待确认、币种不一致、成本未知时不能完成分配。
- 已关账、已删除或已离开项目的已有日成本保留，从月成本预算中扣除，仅剩余预算分入可分配项目。当前未关账月份的旧部分成本按新规则重算，其他历史已计价记录保留。既有请假扣减继续在完整基础成本分配后应用，不恢复请假费用。
- 人员表使用与日核算相同的整月分配金额，包含月内早期已结束项目的实际份额，不能只用最后一天比例覆盖整月明细。

## 2026-09-30 负责人按合并总额分摊

用户澄清办理口径：第一步继续分别核对日常费用和人员/IT来源明细；第二步融合成一个总额，负责人只填一套比例，不再分别分摊。新的负责人记录使用现有 `cost_pool` 字段的 `COMBINED` 值（varchar(16)，无需迁移）。月总额按最大余数法分到负责人，比例合计100%才能下发；每人收到一笔任务，再将合并金额分到本人业务项目。

旧草稿按既有金额权重合并同一负责人；若只设置过日常费用比例，沿用这一套相对比例计算合并总额。既有已设置池中尚未分完的比例仍保持未完成，不把它自动填满。显示转换结果供核对，用户暂存或下发时才替换旧记录。历史已下发/已结算记录保留原比例、金额、项目及来源口径；退回之后可采用合并分摊。沿用上月比例同样兼容旧的两类记录。

IT来源继续单独保留净亏损与转出快照。项目接收合并成本，IT转出仅取其中 `IT净亏损 / 月合并总额` 的份额；普通费用和公共人员成本不从IT项目抵减。部分负责人提交只转出已提交部分的IT份额，全体提交后IT转出合计精确等于净亏损，重复同步、月结、退回保持原有守恒。月结后的普通调整仍只增减日常费用，不能用合并总额削减已封存的人员或IT来源。

### 历史公共费用扣除与项目比例复制兼容

重新分摊前，从月费用总额中扣除已删除、已关账或已不存在项目上仍保留且不在当前负责人项目分摊记录中的正向日费用。IT负向转出不作为扣除项；仍由当前负责人项目记录承载的已关账费用不重复扣除。只改变本次可分配金额，不修改原月账总额和历史项目记录。

本地9月账单保留项目11「出海短剧」230.33元，因此待分配额为72,209.83 − 230.33 = 71,979.50元。原90%/10%比例预览为刘鑫64,781.55元、石头7,197.95元。IT份额的分母改为本次可分配金额；全部提交后仍完整转出10,643.17元，接收项目正向费用加历史保留额正好等于原月总额。若已暂存的合并金额与最新预算不符，必须重新保存，后端下发校验会阻止旧金额直接下发。

负责人复制上月项目比例时，支持从旧EXPENSE/PERSONNEL记录转为COMBINED：按上月实际分配金额合并同一项目的权重。无效项目过滤后仍保持缺口，部分已分配记录不自动补满。已有同类COMBINED记录直接沿用其比例。

含IT转分的已关账或删除接收项目、来源项目不能直接退回，以免清除一端而保留另一端导致成本失衡。普通历史费用的退回和保留流程继续有效。
