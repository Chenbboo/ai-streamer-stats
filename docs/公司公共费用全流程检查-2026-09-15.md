# 公司公共费用全流程检查

本次检查覆盖费用设置、月账生成、老板分配、负责人项目分摊、月结、历史调整、经营结果及项目结项前置条件。发现并修复三处问题，已更新本机服务。

## 修复的问题

| 问题 | 实际影响 | 修复 |
| --- | --- | --- |
| 分摊快照只允许 100 字项目名，项目本身允许 160 字 | 合法的长名称项目保存分摊时报数据库错误 | V098 将分摊名称字段扩至 160 字，保留原有记录 |
| 可选负责人未检查人员档案的离职状态 | 离职档案与账号状态不一致时仍能被选中 | 查询排除离职人员；保留无档案的历史有效账号兼容 |
| 可选负责人未检查所属部门状态 | 停用部门中的账号仍可被接口分配新费用 | 查询排除停用部门人员，历史已分配记录保留 |

| 页面交互 | 财务页面 26 类、负责人页面 12 类、日参考及经营结果 5 类场景通过；接口全部模拟，无真实业务写入 |
| 数据库变更 | V098 在副本执行两次，原有分摊记录一致；本机执行后原有 2 条分摊记录及金额一致 |
| 服务更新后访问 | 登录、用户信息、立项列表与选项、项目列表接口和前端 81 端口通过 |

实际接口流程使用独立数据库 `public_expense_verify_20260915_112646`、测试公司、18085 端口和独立 Redis 数据库。未在正式业务库创建测试账单或付款。

重点验证了以下行为：

- 年度金额分月及尾差、月费用生成重试、金额小数位限制、费用规则版本冲突。
- 公司和部门隔离、负责人身份、跨公司负责人、重复分配对象、比例超过 100%、不足 100% 草稿禁止下发。
- 负责人只能修改本人分摊，不能选择他人项目或不同币种项目；两级金额精确到分且合计一致。
- 退回后清除旧项目分摊，核实金额后重新下发；暂估未确认或负责人未提交时禁止月结。
- 当前月份不能提前月结；同时发起两次月结，仅一次成功且只生成一组成本流水。
- 月结测试费用为 20.01 元，三个项目成本合计 20.01 元，经营结果只扣除一次；追加 +1.23 和 -0.23 后，成本合计和经营结果同步变为 21.01 元。
- 相同调整请求重试不重复入账，改变重试金额被拦截，调整后费用不能为负；冻结项目不能新增公共费用调整。
- 沿用上月负责人及项目比例；已月结原始费用禁止覆盖；日均参考不作为第二笔月成本入账。
- 未生成月账、未分配和未月结费用的结项阻断，以及项目实际起止日期、历史调整和零分摊的查询结果。

本次是功能、权限、金额和并发重复操作检查，不是高并发容量测试。结项前置条件通过查询和已有后端测试验证，未对正式项目执行结项或发放动作。
