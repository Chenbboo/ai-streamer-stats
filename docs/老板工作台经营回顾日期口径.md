# 老板工作台经营回顾日期口径

2026-09-14，本地实现。范围为 `/business/boss` 的经营回顾与收支下钻，保留待办、人员成本设置、项目负荷和项目状态的实时语义。本次不涉及生产发布、数据迁移或历史金额回填。

## 日期与接口

- 工作台默认请求 `GET /business/accounting/boss-overview?bizDate=yesterday`，也支持 `today` 和合法的 `yyyy-MM-dd`，禁止未来日期。
- 后端以 `Asia/Shanghai` 解析相对日期；返回 `bizDate`（经营日期）与 `currentBizDate`（当前业务日期）。前端标明北京时间。昨天是前一自然日，无结果时不跳到上个工作日。
- 不传日期的 HTTP 调用及原两参数服务方法仍查询今天，保持 AI 的“今天经营怎么样”、工具描述、证据日期与数据一致。
- 汇总、分币种金额、项目排行、公司分项和日期内完整性检查使用同一经营日期与原老板授权范围。工作台使用 `summary`、`summaryByCurrency`；旧 `today` 字段保留为兼容字段。
- 昨日／今日选择在页面刷新、重新激活及跨日后重新解析；指定历史日期保持固定。快速切换时丢弃过期请求结果。

## 结果完整性

| 状态 | 展示 |
|---|---|
| 加载／请求失败 | 显示加载或重试提示，隐藏金额和正常结论 |
| NO_DATA | 没有已生成日结果，金额显示 `—`，不解释为零收支 |
| INCOMPLETE | 有待生成日结果、待计价成本、未完成收支或工作；有日结果时只展示已核算部分 |
| AVAILABLE | 存在日结果且上述已记录问题为零，显示“已有核算结果”；不宣称所有未录入业务均已完整 |

接口返回已生成结果数量、最早／最晚数据截止时间、日期内待计价成本、草稿／退回收支和未完成工作数量。金额继续按币种分别展示，利润公式与既有日结果版本保持一致。

待生成日结果按已有经营事实、成员工作日成本、实际工作／计划工作日、旧比例投入分别判断；不再仅凭成员工作日模式的有效投入安排判断休息日缺报，历史项目也不会因今天已关闭而漏掉已有来源的历史日结果缺失。

完整性是对已有来源的核对，不是对所有未录入业务的证明。工作台只读已有记录，不为填满卡片同步、补录或重算成本。成员工作日计价继续使用原日历与后台任务；尚未生成的来源不能伪造为零金额。总览多次查询在同一只读事务内执行。

“全部历史草稿”数量独立保留，不能把它解释为昨日草稿。实时历史待办继续沿用原待办接口。

## 异常、下钻与操作

- 所选日期经营异常包含该日亏损与每日预算异常；每日预算明确按当前配置核对，不宣称为历史预算配置快照。
- 当前需关注包含当前项目归属缺失与累计预算异常；累计预算用不晚于当前业务日期的最近日结果，显示来源日期并按当前预算核对。已经关闭／取消的项目不列为当前累计预算问题。
- “未发现异常”只描述已生成日结果中的当日亏损与每日预算；无结果、数据不全和请求失败均不显示此提示。
- 查看当日收支及异常下钻传 `dateFrom=dateTo=实际来源日期`，项目异常同时传项目 ID。收支页继续支持原独立入口和日期选择。
- 收支页的待计价数量改为遵循当前日期范围、项目、公司和用户权限，避免昨日明细显示全部历史待计价总数。
- 录入收入／支出仍是独立操作入口，不继承经营回顾日期；真实业务日期及原后端限制不变。
- 单人／批量成本设置的默认生效日独立取北京时间当前日期，避免查看昨天导致倒填成本政策。
- 新增经营回顾文案提供中文与越南语；本轮未扩大为原工作台所有历史文案的翻译改造。
