# 本地请假功能下线

按用户要求，本系统不再办理请假申请，考勤继续由飞书自动同步。

- 负责人工作台移除申请、撤回、取消、申请表单和申请记录面板；人员说明改为考勤由飞书自动同步。
- 老板工作台移除请假和销假审批、证明附件入口；后台待办列表、待办计数不再查询请假申请。
- 删除四个本地请假 HTTP 接口、对应前端 API、项目服务方法及申请和审批写入 SQL。
- 删除 AI 的 `project.member.leave.set` 能力，旧确认卡不能再执行本地请假。
- 项目结项与核算关闭不再被历史未完成请假申请阻挡。
- 不删除历史请假表和记录，保留历史核算、历史附件授权及飞书同步链路。本次不需要数据库迁移。

验证包括：Chrome 模拟接口验证两个参项人员正常显示，旧申请数据也不会恢复申请和审批入口；四个旧 HTTP 地址返回 404 且不调用业务服务；运行时类路径不再含请假 AI 能力；项目核算关闭状态不再包含请假阻挡项；飞书同步、轮询、目录及接口权限测试通过；前端生产构建通过。

工作区有其他任务同时构建，直接运行测试时曾遇到输出目录被清理导致缺失类，随后改用 `work/leave-removal-build/backend` 的独立源码副本完成验证和打包。完整回归还发现与本次变更无关的 `BusinessProjectWorkspaceAccessTest` 使用 ACTUAL_WORK_V1 旧测试数据，而当前资源选项已筛选 MEMBER_DAYS_V1。该类的失败保留在 `work/local-leave-removal-isolated-build.log`；最终构建明确排除该类，未修改它的业务规则或断言，不能将最终结果理解为工作区所有测试全部通过。

本机已安装独立构建的完整 JAR，替换前备份为 `work/backend-before-leave-removal-1788848383855.jar`，并验证新旧安装文件哈希匹配与 8080 健康检查成功。此次不是覆盖单个 class；运行包已完整移除请假 AI 类。
