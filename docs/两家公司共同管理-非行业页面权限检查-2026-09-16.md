# 两家公司共同管理：非行业页面权限检查

日期：2026-09-16。范围：排除直播和珠宝，检查项目、人事、财务、工作台、AI、飞书及系统管理入口。

检查方式：当前工作区页面、组件、控制器、服务权限判断、Mapper 查询和菜单迁移静态核对。未修改业务权限，未以真实老板账号操作数据库；不把源码结论当作线上验收结论。工作区公共人员费用等未提交改动纳入观察，但其部署和验收状态未验证。菜单迁移说明预期导航，不等于运行数据库菜单状态。

## 1. 结论

多数业务页面可以支持两位老板共同管理两家公司。公司、项目、人员、币种、月份等数据归属仍须独立。共同管理应通过“账号—授权公司—功能—操作”明确配置。

目前同时存在三种权限逻辑：老板角色可跨公司、仅公司组织负责人、仅项目归属老板。只给两人相同菜单不足以实现共同管理。

个人工作记录、个人待办、AI 会话与账号密码仍保持个人边界。技术配置另授专门权限。项目主负责人和归属老板作为责任与默认通知对象保留，不应把共享管理实现为反复更换归属老板。

## 2. 页面清单

下表“建议”是目标行为，并非当前已经实现。

| 页面或入口 | 当前代码情况 | 共同管理建议 |
|---|---|---|
| 老板工作台 | 多项经营、项目和待办查询按项目归属老板过滤 | 两人可查看授权公司的经营与项目；审批待办对有权处理者可见，一人处理后同步消除 |
| 立项表单、我的申请 | 申请详情主要允许申请人、归属老板或管理员；修改、启动校验申请人身份 | 两人可查看授权公司立项；本人草稿与启动保留经办责任，需要代办时单独设计并留原申请人 |
| 全部立项申请 | 目录可见不等于能打开、编辑；目录结果主动将操作标记设为 false | 按授权公司显示；详情权限与目录保持明确一致 |
| 项目中心、主子项目 | 列表 SQL 和详情服务主要按归属老板或参与关系过滤 | 两人可管理授权公司项目；主子项目归属、项目负责人和成员身份保留 |
| 项目 KPI／结果 | 设置和确认有独立的归属老板判断 | 两人可获设置、复核权限；项目负责人填报职责继续保留 |
| 奖金激励 | 奖励规则、申请查看和核准区分负责人、归属老板；核准限制归属老板 | 两人可按公司授权查看、维护和核准；不能审核本人申请 |
| 奖金分配与发放 | 分配由实际主负责人提交；核准限制归属老板且非本人；付款允许归属老板或授权公司财务 | 两人可获核准和付款登记权；保留额度、防重复、成本先确认和经办记录 |
| 人员管理 | 老板角色目录范围较宽；编辑、停用、密码重置仍检查用户数据范围 | 两人可管理授权公司员工；所属公司、部门、任职及调动历史独立 |
| 部门管理 | 业务菜单支持老板使用；服务调用部门及用户数据范围检查 | 两人可维护授权公司组织；不能把公司之间的组织和人员无记录混移 |
| 员工菜单权限 | 老板可设置目录权限；该服务的目标范围判断主要验证老板角色 | 增加目标人员公司范围；授予权限不能超出经办老板可授范围，不能当作全系统角色授权替代品 |
| 人员成本设置 | 成本接口允许具备成本权限的老板跨公司；人员列表的金额和按钮标记仍关联公司负责人等条件 | 统一查询、金额可见和保存权限；成本查看与修改可分别授予 |
| 项目核算与收支 | 查询和写入仍有按归属老板或主负责人限制的入口 | 共享授权公司的核算查看、确认、冲销；收入花费原填报人与审核人留痕 |
| 公司公共费用 | 老板角色可访问多个公司；按公司、月份、币种建账并检查账单版本 | 可由两人共同配置、下发、退回和月结；增加明确授权公司清单 |
| 公共人员费用子页 | 当前增量代码按公司、月份、币种计算人员成本池，并核对直接项目成本 | 共享管理但保持人员来源、直接成本和公共分摊守恒；本轮未验证实际启用状态 |
| 公司税率弹窗 | 老板角色或公司组织负责人可读取公司列表并设置税率 | 两人可设置授权公司的税率，保留版本、理由和关账快照 |
| 员工考勤／假勤查询 | 按公司实际负责人或显式读授权判断 | 两人均可获公司查询权，保留本人查询入口与公司范围 |
| 飞书集成 | 技术配置使用集成权限；公司、人员映射分别绑定连接 | 共同查看同步状况；连接、映射和密钥配置只给明确授权的维护人 |
| 假勤接入验收／来源切换 | 与飞书共用组件，但关键业务操作限定公司实际负责人 | 若两人需处理，另设公司验收和来源切换权限；不能仅放开技术配置权限 |
| 负责人工作台 | 页面围绕本人负责项目、收支填报、成员与分摊；部分按钮仅按老板菜单权限预判 | 老板可监督和授权代办，代办应明确实际经办人；不能把主负责人身份改成老板 |
| 我的安排 | 按当前用户组织任务、持续工作和工作填报 | 保持个人入口；老板查看员工安排通过管理查询，不能冒充本人填报 |
| 我的工作台（旧组件） | 旧个人跨项目待办页面仍有源码；早期菜单已调整为负责人工作台 | 保留个人数据边界；实际是否仍有运行入口需核菜单 |
| 资源与实际工作（旧入口） | 当前页面重定向到项目资源页；V075 隐藏停用原独立菜单 | 不按独立的新业务页重新开放，统一检查项目内资源组件 |
| 老板 AI 助理 | AI 业务调用仍受业务服务权限控制，会话按当前用户读取 | 两人可分别分析授权公司；个人会话与操作确认卡不共享身份 |

## 3. 项目内部不能遗漏的子页面

| 子页面或操作 | 当前限制／需要处理的点 |
|---|---|
| 计划与预算变更 | 查看限项目相关人；变更复核要求独立的归属老板；预测维护限主负责人。共享复核必须保留申请人与复核人分离 |
| 任务、持续工作、里程碑、风险 | 多数依赖项目管理权限；菜单放开后仍受项目服务限制 |
| 人员安排、投入权重和调配确认 | 有主负责人、相关项目负责人确认及当前版本约束；老板监督权不能自动替代相关负责人确认 |
| 主子项目进度、历史汇报与通知 | 服务按项目可见性裁剪子项目历史；通知读取绑定当前用户。共享读取和个人已读状态需分别处理 |
| 成果验收、阶段验收 | 保留负责人提交成果，两位获授权老板可复核的目标需统一到服务端 |
| 交付与结算 | 结束交付、核算关闭仍检查归属老板；前端读取 canClose 等服务端能力标记 |
| 管理费规则、结算、实付 | 服务直接判断归属老板，不能仅依赖付款菜单；付款有关账状态要求 |
| 关账后调整 | 前端 canView/canReview 和后端审核都绑定归属老板等身份，必须一起改 |
| 离职与交接 | 依赖人员数据范围与未完项目、任务交接；保留生效日期。老板和管理员受保护账号另走专门交接 |
| 附件、缩略图、下载 | 单独判断项目主负责人、成员、归属老板或原发起人，必须同步公司授权，否则可能页面可见但附件被拒 |

## 4. 平台和个人页面

| 页面组 | 建议 |
|---|---|
| 通知公告、已读记录 | 两人可授权共同发布。当前公告模型和主要查询未见公司归属／受众公司字段；若需分别发布给两家公司，应补受众范围，不能用创建人代替受众 |
| 个人资料、头像、修改本人密码 | 保持个人管理；员工账号管理走人员管理授权 |
| 系统用户、角色、数据权限、角色分配 | 与业务“员工菜单权限”区分。公司老板可通过受限业务入口管理员工，不默认开放系统级角色授权 |
| 系统部门、岗位 | 公司部门管理优先走业务部门页；岗位模板可共享，具体组织归属按公司保存 |
| 系统菜单、字典、参数设置 | 平台配置，另授维护权限；公司业务规则应拆到公司设置，不把全局参数当公司设置 |
| 在线用户、操作日志、登录日志 | 可按需要授权查看和审计；强制退出、解锁、删除或清空日志是独立操作权限 |
| 定时任务、任务日志、服务器、缓存、数据监控 | 技术运维入口，与老板业务共同管理分开授权 |
| 代码生成、接口文档 | 开发维护工具，不纳入普通老板公司管理菜单 |
| 登录、注册、锁屏、跳转、错误页 | 通用入口，不承载两家公司业务共同管理权限 |

平台页面核对以入口和控制器权限为主，本轮未进行系统配置写入或逐项运维操作验证。

## 5. 确认的主要不一致

1. 公共费用和税率按老板角色放开多家公司，项目、奖金及关账仍限定原归属老板。
2. 员工目录、成本列表按钮、成本保存接口对公司范围和老板身份的判断不同。
3. 项目页面存在按 business:boss:view 推断管理能力的按钮，而服务端继续限制归属老板；正式改造应由后端返回对象级 canView/canEdit/canReview/canPay/canClose 等能力。
4. 关账后调整、附件、AI、待办查询各有独立权限入口，必须同时纳入。
5. 公司组织负责人目前是单一身份引用，不足以表达两位老板共同管理；保留负责人字段，新增管理授权关系。
6. 公司授权与页面功能授权需要同时成立，不能用给老板全部数据范围或管理员角色代替。

## 6. 建议落地与验收顺序

1. 统一账号的授权公司清单，并区分查看、维护、审核、付款登记、关账、授权员工等操作。
2. 优先改老板工作台、项目中心、人员与成本、核算、公共费用、税率的范围和按钮能力。
3. 再改计划复核、KPI、奖金分配、管理费、验收、关账与调整单；保留同一业务只生效一次和自审限制。
4. 对齐附件、AI、通知与待办，以及飞书公司读授权和关键切换操作。
5. 使用隔离账号验证：甲管两家公司、乙仅管一家；两人均管两家；第三家无授权；授权撤销；跨公司直接请求；本人申请审核；并发审核／付款／月结；历史账冻结；页面与 API 一致性。以上是后续验收计划，不是本次已执行测试。
