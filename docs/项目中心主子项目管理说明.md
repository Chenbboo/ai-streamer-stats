# 项目中心主子项目管理

项目中心由服务端按主项目分页，子项目不计入分页总数。首次进入只加载当前页主项目，默认全部收起。点击行首箭头时按需加载对应子项目，各行独立展开和收起。子项目复用列表字段，以缩进和浅色背景区分。

搜索和筛选命中子项目时，主项目纳入分页，自动展开并高亮定位对应子项目。子项目可见范围遵循既有数据权限；仅参与子项目的用户看到脱敏的主项目层级节点，不获得主项目详情权限。

主项目支持新增子项目、编辑、查看、删除；子项目支持编辑、查看、删除。成员和风险列可点击查看完整清单。编辑或删除子项目仅更新对应子列表。

新增子项目复用现有立项表单，自动绑定主项目并以禁用字段展示；新建主项目时隐藏该字段。子项目表单在原“归属老板”位置显示必填的“子项目负责人”人员选择框，并合并重复的负责人输入。后台继承主项目的归属老板；申请人和所选实际负责人分开保存，正式启动时将所选人员写入项目负责人字段并建立 OWNER 成员身份。人员预算和初始人员计划使用所选负责人。

主项目表单、新建权限及“保存立项申请 → 确认启动 → 创建正式项目”的流程保持不变。创建者仍有主项目管理权限时，可查看自己创建的子项目；子项目的后续管理权限沿用既有规则。返回项目中心后刷新原主项目的子列表，保留分页和其他展开状态。

业务规则：

- 治理方式沿用轻量、标准、重点监管，结项方式单独设置。
- 主、子项目归属同一位老板，负责人调整沿用原有详情交接入口及权限。
- 人员计划、预算、收支、量化目标、成本政策和验收基线均绑定各自项目 ID，独立存储、独立核算。
- 仅支持“主项目 → 子项目”两级结构，保存申请及正式启动均执行父级校验，父子归属不可修改。
- 冻结后的范围、日期和验收基线通过项目计划与变更调整。
- 新增沿用 business:project:proposal:add 和既有立项权限；编辑、删除使用 business:project:edit。关联主项目时由服务端再次检查管理员、归属老板、主负责人或副负责人身份。

删除主、子项目均需二次确认。服务端锁定项目并检查全部未删除的子项目；存在子项目时提示“该项目包含子项目，请先删除所有子项目，再删除主项目”。采用逻辑删除保留历史记录，创建子项目使用相同父级行锁，避免并发产生孤立子项目。

层级复用 biz_project.parent_id 和 del_flag。部署时先执行 V089__subproject_proposal_owner.sql，增加立项申请的 assigned_owner_user_id 和 assigned_owner_name，再更新前后端。历史子项目申请按已创建项目负责人或原申请人回填，正式项目继续使用 main_owner_user_id 和 main_owner_name。

验证范围包括前端生产构建、层级工具测试、后端服务校验、主项目分页与子项目搜索的 Mapper 集成测试、权限隔离及控制器权限测试。
