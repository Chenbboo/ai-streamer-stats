# 自动化测试与一键检查

更新日期：2026-09-24。适用于当前 Vue 3 前端和 Maven 后端。

## 日常使用

在仓库根目录执行：

```powershell
.\check.bat
```

也可以从其他目录用绝对路径调用。脚本按自身位置定位项目，不依赖终端当前目录。

需要 PATH 中已有 Java 8、Maven、Node.js 20 或更高版本，以及 pnpm；首次使用先在 `frontend` 执行 `pnpm install --frozen-lockfile`。当前验证环境是 Java 8、Maven 3.9.12、Node.js 24.12.0。依赖未缓存时 Maven 需要下载依赖。

检查顺序：

1. 后端 `mvn -B -ntp test`，运行全部模块的默认测试。
2. 前端 `pnpm test`，自动发现 `src` 下所有 `.test.js` 和 `.test.mjs`，没有测试文件时返回失败。
3. `pnpm run check:i18n`，检查中越文案、插值及语言工具测试；作为提示项，珠宝 ERP 暂无越南语验收要求，不阻止发布。
4. `pnpm run build:prod`，执行前端生产构建。

后端测试、前端测试或构建失败会使最终退出码为 1；翻译检查的发现仍显示在报告中，但不改变最终退出码。后续检查仍执行，方便一次看到所有问题。成功退出码为 0。结果写入已忽略的 `logs/checks/<时间-PID>/`：每阶段日志及 `summary.json`。后端汇总只读取本轮新生成的 Surefire XML，列出通过、失败、错误及每个跳过项的原因；核心模块缺少新报告也算失败。前端用例统计见 `frontend.log`。

日常检查不启动应用、Redis、后台任务或浏览器，不部署。构建会更新本地 `frontend/dist`。默认后端 SQL 测试使用 H2 内存库；真实 MySQL 测试的启用条件见下节。

## 跳过项与验证边界

2026-09-24 合并最新 ERP 提交后的一键检查结果：后端发现 **1,431 项，1,399 项通过、32 项跳过、0 失败、0 错误**；前端 **54 项通过**；生产构建通过。翻译检查发现的 114 项均在 `src/views/jewelry`，按当前要求仅提示，不阻止发布。

32 项跳过分为：

| 数量 | 测试 | 原因 |
| --- | --- | --- |
| 10 | `BusinessFlowMysqlIntegrationTest`、`BusinessBossAwardPendingMysqlTest` | 未设置 `BUSINESS_FLOW_TEST_DB` |
| 5 | `BusinessBossReviewMysqlTest` | 未设置 `BOSS_REVIEW_TEST_DB` |
| 17 | 旧 AI 直接立项流程 | 现有用例显式停用，已由立项申请页面替代 |

前两组需要预先准备结构与当前代码匹配的独立本地 MySQL 测试库。现有测试连接 `127.0.0.1:3306`，库名分别要求 `flow_verify_` 加数字、`boss_review_test_` 加数字；密码由 `BUSINESS_FLOW_TEST_PASSWORD`、`BOSS_REVIEW_TEST_PASSWORD` 读取。脚本继承这些环境变量，不自动创建或复制数据库。不要将其配置为业务库；夹具虽在测试后回滚，仍会执行写 SQL。本轮未启用这 15 项，不能视为真实 MySQL 验证通过。

“检查通过”也不代表真实登录鉴权、浏览器业务闭环、飞书联调或生产数据对账均已完成。已有翻译专项浏览器脚本 `frontend/scripts/check-i18n-browser.mjs`，依赖单独的预览服务、Playwright 和浏览器，不纳入默认检查；使用方法见《越南语界面翻译与验收-2026-09-22》。该脚本模拟 API，不等同于完整业务端到端测试。

## 本轮修复

- 固定 Maven Surefire 3.2.5，与本机已实际执行 JUnit 5 的版本一致，避免依赖 Maven 隐含插件版本。
- 将最新珠宝 ERP 测试中的 Java 9 集合工厂写法改为 Java 8 兼容写法；仅调整测试代码，不改变业务实现。
- 补齐“经营回顾公司”“当前公司：{0}”“请选择所属部门”的越南语，保留插值参数。
- 珠宝退供预警测试原先在 H2 1.4 查询计划计算中长时间运行。保留原 46 个用例及金额、日期、库存断言，把生产 SQL 的公共子查询按依赖顺序原样执行到连接级临时表，再验证原过滤条件。单类运行约 2 秒全部通过。没有修改生产 SQL，也没有升级 H2；这验证查询结果，不能代替 MySQL 对完整 SQL 的执行计划检查。
