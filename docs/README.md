## 1. 阅读顺序与冲突优先级

1. 判断“代码已经实现了什么”，以当前代码、迁移文件及实际执行记录为准；旧盘点文档只证明其注明日期的状态，本地代码不等于已部署版本。
2. 判断“本轮已经做到哪里”，先读《P1-P4-三系统实施与验收记录》；判断产品模型再读《三系统拆分方案-审阅版》《标准产品蓝图》及配套流程。P1–P4 首轮代码、迁移与菜单已本地实现；真实飞书切换、生产发布和对外标准产品验证分别记录，不用代码完成代替这些结论。
3. 新版标准产品设计替代旧公司经营文档中已冲突的目标方向；旧流程在未切换存量项目中仍可能有效，不能据新文档直接改写历史数据或批准责任。
4. 直播统计口径继续以《统计口径说明》为准；珠宝库存、成本、审批和红冲规则继续以《珠宝ERP第一阶段需求设计》及当前迁移为准。
5. 历史快照不得直接作为全系统当前实现或新开发依据。设计演进同步总体摘要和详细引用，不把尚未实现的状态、接口、字段写成已完成。

## 4. 当前实现核对摘要

本节对应本地 `codex/system-baseline` 的 P1–P4 开发改动，迁移文件至 V067；本地开发库已验证并应用，未推送或部署生产。准确测试及 API/UI 验收证据见[总记录](./P1-P4-三系统实施与验收记录.md)。

- 新基础模板无预算、无人员费率、无 KPI、无奖金可启动；受控模板由不同归属老板审批，旧立项按原版本续办。
- 新 KPI 方案独立确认指标，不自动产生奖金；HR 奖励核准后生成唯一待确认成本，核算再确认。旧联动及历史 `SUBMITTED` 继续兼容。
- 新创建项目采用分离策略，交付结束后核算保持开放，已有 KPI/奖金及合法迟报费用可续办，再由归属老板独立关账；旧项目保留原关闭规则。
- 新人工成本按确认分钟与有效费率计价；未记录和缺费率保留未知/待计价，旧项目原比例方法保持。内部费率独立进入财务菜单及权限。
- 飞书只读适配器、人员映射、同步修订、假勤查询及受控切换已实现。真实授权及六类企业样本未验收前，不能声称已替代本地假勤来源。

## 5. 下一阶段决策摘要

- 统一平台下设置项目管理系统、人力资源管理系统、财务与管理核算系统，系统内再设功能菜单；不采用五个平级业务入口，也不要求三个独立部署。原有直播、珠宝作为行业应用保留。
- 项目 KPI 归项目系统；员工绩效、奖金激励在人力资源系统中分设独立模块；成本确认、支付记录归核算／外部工资支付系统。个人分配和支付仍为后续能力，各自负责写入和审批，关联查询不扩大权限。
- 工作日历决定可用容量，单位政策决定人天换算；计划比例、实际投入和出勤分别保存。
- 项目交付、项目核算、绩效、奖励和支付各自有状态；模板控制必要业务门槛，保留旧项目流程版本。
- 飞书办理考勤与假勤，网站接入必要结果和同步状态；出勤不替代实际项目投入，未知数据不转为缺勤或零成本。
- P1–P4 首轮实现覆盖模板与实际工作、交付/核算分离、独立奖励和飞书接入守卫。完整员工绩效、个人分配/发薪、支付反馈与总账留后续产品版本。

## 6. 文档变更与实施验证规则

- 新设计登记版本、日期、状态和范围；同一变更同步总体设计的原则、生命周期、权限及验收摘要。
- 历史正文原则上保留，只在顶部增加替代说明、快照日期及使用限制。
- 描述现状必须提供代码、迁移或已执行验证依据；真实数据库、外部接入和生产部署未验证时明确注明。
- 开发前核对流程版本、原确认职责、历史金额及各入口状态限制，不能仅移动菜单或删除前端校验。
- 权限改动验证创建人、复核人、管理员及不同公司／项目的数据范围；页面、接口、AI 和批处理采用一致服务端规则。
- 成本口径或统计 SQL 修改前核对真实样本；后端服务运行聚焦测试，前端改动运行 `pnpm run build:prod`，受影响双语页核对中文和越南语。
- 文档设计检查不代替代码测试、真实飞书联调、数据对账或生产验收。
