# 奖金分配与发放

2026-09-09，本地实现。当前由项目归属老板核准分配并登记实付；不连接银行，不生成工资单，不重复计入成本。

## 流程与金额

奖金激励新增“奖金分配与发放”页签，从已核准奖励建立个人分配批次。负责人选择项目成员、填写金额或占核准奖金总额的比例，并填写个人及整体说明。历史离项成员可领取参与期间奖金。比例金额按两位小数四舍五入，合计超额则拒绝保存，可保留未分配余额。

分配状态：草稿 → 待核准 → 已核准／已退回。退回后可编辑并重新提交；草稿或退回记录可撤销。每个批次可保留部分奖金，剩余额度可另建批次。草稿、待核准、退回和已核准批次都占用额度，撤销后释放。已核准明细不能直接修改或删除。

老板展开已核准分配，逐人登记实付金额、日期、方式、流水或收据编号、上传凭证和说明。支持分批发放；个人显示待发放、部分发放或已发放。付款日期限分配核准日至今天，累计实付不能超过个人核准金额。奖金成本必须先确认入账；成本被退回或冲销时禁止继续登记付款。分配及付款可在项目关账后继续登记，因为不改变已确认经营成本。

分配和付款均写入独立表，不调用成本生成、确认或重算服务。已存在有效个人分配的奖励不能从原奖励页面直接撤销。实际付款记录本版保留为不可覆盖的登记记录，不提供删除或自动退款。

## 权限

| 操作 | 菜单权限与服务端约束 |
|---|---|
| 分配、提交、撤销草稿 | business:incentive:apply；必须为实际项目主负责人，编辑／重提须为原创建人 |
| 核准或退回 | business:incentive:approve；必须为项目归属老板，不能审核本人创建的分配 |
| 登记实付 | business:incentive:pay；当前由实际项目归属老板操作，同公司其他老板不能代发 |
| 可选财务经办 | bonus_payment_finance 专用角色及 pay 权限；额外检查账号所属部门位于项目公司范围内，没有自动给实际用户绑定该角色 |
| 查看全项目分配 | 主负责人、归属老板、显式管理员；获授权的公司财务只读取公司范围内分配，不开放原奖金方案／申请详情接口 |
| 查看个人奖金 | 领取人仅见自己的已核准金额及实付记录，不返回其他人的明细、项目奖金总额或包含全员快照的操作事件 |

V077 给现有 company_owner、hcm_incentive_approver 角色增加 pay 权限；服务端同时校验实际项目身份。project_user、project_deputy 增加奖金菜单读取权限；原奖金 workspace 仍只允许负责人、老板及显式管理员，普通成员只能使用新的个人过滤读模型。已有登录会话新增权限需重新登录后加载。

## 数据与并发

新增 biz_bonus_allocation、biz_bonus_allocation_line、biz_bonus_payment、biz_bonus_event 四张表。保存后的每版分配及审核、付款操作均留快照和操作人／说明。请求标识按项目唯一；付款额外按个人分配明细和付款流水去重，相同请求内容可重试，不同内容复用标识会被拒绝。

写操作先锁定项目行，重新读取分配／来源奖金再校验额度；分配状态使用版本号保护。来源奖励撤销也使用相同项目锁，防止与分配并发冲突。
