# 项目 KPI 与奖金设计

> 版本：v1.1
> 日期：2026-08-20
> 状态：已确认，作为第一阶段开发与验收基线
> v1.1 变更：增加执行中项目的 KPI 合规待办，以及验收通过/直接结项前的 KPI 结算硬性校验。

## 1. 已确认范围

第一阶段只处理项目级 KPI、项目级人民币奖金池和项目经营成本，不处理个人 KPI、个人奖金、真实工资或奖金向个人分配。

- 老板为归属自己的项目设置并发布 KPI 目标和综合阶梯奖金。
- 项目负责人查看已发布目标，填报项目实际结果和说明，提交结算。
- 老板确认或退回结算；确认后系统锁定结果并立即将项目奖金计入项目成本。
- 正式项目进入 `ACTIVE` 后必须补齐已发布 KPI 方案；尚未发布时列入老板工作台待办。
- 项目验收通过或直接结项前，至少要有一个经过发布流程生成的 KPI 方案，且所有已发布方案都必须完成老板确认；未来尚未到期的方案也不能遗留到项目关闭后。
- 人员成本继续使用老板维护的内部核算成本，通过既有投入规则分摊到项目。
- 项目奖金池与内部人员成本分别核算，均参与项目利润计算。
- 暂不增加财务复核；未来增加财务环节时不得改写已确认的 KPI 结果。

## 2. 业务边界

```text
项目 KPI 结果 → 综合得分 → 阶梯奖金 → 项目奖金成本
内部成本政策 → 人员投入分摊 → 项目人员成本

项目利润
= 项目收入
- 普通业务成本
- 内部人员成本
- 项目奖金成本
+/- 核算调整
```

“项目奖金池”是内部经营核算金额，第一阶段不代表已经向任何员工发放，也不进入个人工资单。

## 3. 角色与权限

### 3.1 老板

- 只能管理归属自己的项目；系统管理员可用于运维验证。
- 新增或调整项目 KPI 目标，目标按版本保存。
- 选择月度、季度或项目周期，设置起止日期。
- 设置综合阶梯奖金，币种固定为 CNY。
- 发布 KPI 方案；发布时快照当前指标、目标、权重和奖金阶梯。
- 确认或退回项目负责人提交的结算。
- 在老板工作台处理本人项目中状态为 `SUBMITTED` 的待确认结算；不能绕过结算直接通过验收或关闭项目。
- 确认后查看奖金成本、项目总成本和利润。

### 3.2 项目主负责人

- 只能查看本人负责项目的 KPI 方案及奖金阶梯。
- 不能修改老板发布的目标、权重、周期和奖金金额。
- 可以逐项填写实际值、结果说明和凭证附件。
- 可以保存草稿并提交结算；退回后可以修改并重新提交。
- 可以查看本项目最终奖金池和分摊后的内部人员成本，不能查看人员成本政策原值。

### 3.3 普通项目成员

- 第一阶段不参与 KPI 配置、结算或奖金分配。
- 继续通过既有任务、持续工作和投入填报提供项目执行数据。

## 4. KPI 方案

### 4.1 指标

KPI 只评价项目，不设置个人考核对象或个人奖金领取人。既有“指标负责人”字段不再用于新方案；如历史数据保留该字段，只解释为数据跟进人。

指标包括：系统生成的稳定编码、名称、类型、单位、目标值、最低值、预警值、挑战值、权重、考核方向、聚合方式、数据来源、生效日期和版本。新建时不允许人工填写编码；调整目标时沿用原编码并生成新版本。

发布约束：

- 至少有一项当前有效 KPI。
- 当前 KPI 权重合计必须等于 100%。
- 目标值必须大于 0。
- 发布后的指标使用快照，后续调整只影响新方案，不回写历史方案。

### 4.2 周期

每个方案只能选择一种周期：

- `MONTH`：月度。
- `QUARTER`：季度。
- `PROJECT`：项目周期。

同一项目不能发布日期区间重叠的有效方案。

发布方案时系统同时创建该周期的 `DRAFT` 结算。周期结束日小于或等于服务器当前自然日时，该方案已经到期，可以由负责人提交结算；周期尚未结束时不能提前提交。

结项校验分两步执行：先检查项目至少存在一个经过发布流程生成、状态为 `PUBLISHED` 或结算确认后转为 `CLOSED` 的方案，再检查项目全部已发布方案的结算是否均为 `CONFIRMED`。因此，只有目标但从未发布方案仍然不合格；存在未来尚未到期方案时也不能提前关闭项目，必须等待周期结束、完成填报和老板确认后再结项。这样可以避免项目关闭后现有结算接口不再允许填报，导致未来方案永久无法封账。

### 4.3 综合得分

第一阶段使用可解释的线性完成率：

```text
正向指标完成率 = 实际值 / 目标值 × 100
反向指标完成率 = 目标值 / 实际值 × 100
单项加权得分 = 完成率 × 权重 / 100
项目综合得分 = 各单项加权得分之和
```

单项完成率最高按 120 分计，防止异常值无限放大奖金。反向指标实际值为 0 时按 120 分计。计算过程统一保留两位小数，使用 `HALF_UP`。

## 5. 综合阶梯奖金

第一阶段只实现综合阶梯奖金：根据项目综合得分命中一个奖金阶梯，得到唯一项目奖金金额。

阶梯规则：

- 第一档必须从 0 分开始。
- 相邻区间必须连续，不能重叠或留空。
- 最后一档不设置上限。
- 奖金不得为负数，币种固定为人民币 CNY。
- 同一结算只能命中一个阶梯，不能累计发放。

示例：

| 综合得分 | 项目奖金 |
|---:|---:|
| 0～79.99 | ¥0 |
| 80～89.99 | ¥10,000 |
| 90～99.99 | ¥20,000 |
| 100及以上 | ¥30,000 |

金额仅为示例，实际由老板逐个项目、逐个周期设置。

## 6. 结算流程

```text
老板维护当前 KPI
→ 老板设置周期和奖金阶梯
→ 系统校验权重与阶梯
→ 发布方案并生成目标快照
→ 项目负责人保存实际结果草稿
→ 项目负责人提交结算
→ 老板退回或确认
→ 系统锁定结果并计算综合得分
→ 系统匹配唯一奖金阶梯
→ 立即生成已确认的项目奖金经营事实
→ 重算结算日项目经营结果
→ 方案和结算封账
```

状态：

- 方案：`PUBLISHED → CLOSED`。
- 结算：`DRAFT → SUBMITTED → RETURNED → SUBMITTED → CONFIRMED`。

状态与结项阻断原因：

| 场景或结算状态 | 业务含义 | 验收通过/直接结项 |
|---|---|---|
| 没有经过发布流程生成的方案 | 只有 KPI 目标或完全未设置 KPI，尚未形成周期快照 | 阻断，先由归属老板发布方案 |
| 未到期方案 | 周期尚未结束，不能提前提交；即使出现异常结算状态也不应提前关闭 | 阻断，提示“尚有KPI考核周期未结束（最近结束日期：YYYY-MM-DD），暂不能结项” |
| 已到期方案缺失结算记录或状态为空 | 历史迁移或数据完整性异常，服务端按“负责人尚未提交”归类 | 阻断，先补齐结果并提交；无法操作时修复结算数据 |
| 已到期的 `DRAFT` | 周期已结束，负责人尚未提交 | 阻断，负责人填报并提交 |
| `SUBMITTED` | 负责人已提交，等待归属老板审核 | 阻断，并进入老板工作台“待确认 KPI 结算” |
| `RETURNED` | 老板已退回，负责人尚未重新提交 | 阻断，负责人修改后重新提交 |
| 其他非 `CONFIRMED` 状态 | 异常或尚未完成封账 | 阻断，先完成或修复结算 |
| `CONFIRMED` | 老板已确认，结果与奖金已经锁定 | 通过该周期的结项校验 |

交付模式项目在老板“验收通过”时执行上述校验；非交付模式项目在老板“直接结项”时执行同一校验。校验必须在服务端完成，页面按钮、AI 能力或其他调用入口都不能绕过。

手工填报要求：

- 实际值必须大于等于 0。
- 每项手工结果必须填写结果说明。
- 凭证附件可选；附件地址沿用系统统一上传组件。
- 每次保存、提交、退回和确认均保留操作人及时间。

## 7. 成本入账

老板确认结算后，系统在结算周期结束日生成一条已确认经营事实：

- 类别：`PROJECT_BONUS_COST`。
- 事实类型：`COST`。
- 来源域：`KPI`。
- 来源类型：`PROJECT_BONUS`。
- 幂等键：按结算 ID 唯一。
- 金额：命中阶梯的人民币奖金；0 元结算不生成经营事实。

确认动作与奖金事实写入必须处于同一数据库事务。重复请求不得重复入账。

## 8. 历史与调整

- 已发布方案、目标快照和奖金阶梯不能原地修改。
- 已确认结算不能直接修改或删除。
- 第一阶段不提供已确认结算调整；如发现错误，由管理员记录问题，后续通过独立调整单能力处理。
- 项目暂停、取消或尚未达到结算条件时不能提交结算。
- 项目进入 `ACTIVE` 后尚未发布 KPI 方案时，老板工作台持续展示合规待办；立项批准仍只执行一次，不因为补 KPI 再增加一轮立项审批。
- 项目验收通过或直接结项前，如不存在已发布方案，或任一已发布方案的结算不是 `CONFIRMED`，服务端必须拒绝状态变更并返回可处理的明确原因，不能只做页面提示；周期尚未结束时明确提示暂不能结项。

## 9. 数据模型

| 表 | 用途 |
|---|---|
| `biz_project_kpi` | 老板维护的项目 KPI 目标版本 |
| `biz_project_kpi_plan` | 项目周期方案与发布快照头 |
| `biz_project_kpi_plan_item` | 已发布 KPI 目标快照 |
| `biz_project_bonus_tier` | 已发布人民币奖金阶梯 |
| `biz_project_kpi_settlement` | 项目 KPI 结算头及奖金结果 |
| `biz_project_kpi_result` | 各 KPI 实际值、说明、凭证和得分 |
| `biz_operating_fact` | 已确认项目奖金成本事实 |
| `biz_project_daily_result` | 含普通业务成本、内部人员成本和项目奖金成本的日结果 |

## 10. 第一阶段验收

- 老板工作台按项目批量展示“未设置、待发布、填报中、待确认、已退回、已确认”等 KPI 状态，并可直接进入对应项目方案；批量概览不能逐项目发起请求。
- 老板工作台把 `SUBMITTED` 结算列入“待老板处理”，展示项目、综合得分、预计奖金及“审核结算”入口。
- 非归属老板不能发布或审核项目 KPI 方案。
- 项目主负责人不能修改目标或奖金阶梯，只能填报和提交本人负责项目。
- 普通成员不能访问 KPI 结算写接口。
- 权重不等于 100%、阶梯不连续或周期重叠时不能发布。
- 手工结果缺少说明时不能保存或提交。
- 老板退回后负责人可以修改并再次提交。
- 老板确认后综合得分、阶梯、奖金金额和目标快照不可变。
- 确认只生成一条项目奖金经营事实，并立即重算结算日利润。
- 0 元奖金可以确认，但不生成 0 元经营事实。
- 项目奖金不产生任何个人奖金、个人工资或个人收款记录。
- 没有已发布 KPI 方案的项目不能验收通过或直接结项。
- 任一已发布方案的结算处于 `DRAFT`、`SUBMITTED`、`RETURNED`、缺失或其他非 `CONFIRMED` 状态时，均不能验收通过或直接结项；全部已发布方案均为 `CONFIRMED` 后才允许关闭项目。
- 未到期结算不允许提前提交，也不应错误出现在老板的“待确认 KPI 结算”中，但它会阻断最终关闭，并提示等待周期结束后再完成结算。
