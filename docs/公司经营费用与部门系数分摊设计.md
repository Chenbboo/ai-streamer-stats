# 公司支出、成本与部门系数分摊设计

> 版本：v0.2｜日期：2026-09-14
> 状态：需求设计稿，本轮新增能力未实现、未迁移、未部署；可复用的现有能力单独说明。
> 已确定方向：公司支出统一登记和汇总；公共经营费用按部门分摊，各部门系数可调整；实际付款与当期成本分别统计。部门专属费用直接归属，已有项目和奖励来源关联复用。
> 本稿建议：按公司、费用类别维护系数及生效月份，按月预览并确认分摊。审批、精度、界面和更正步骤属于设计建议，不表示用户已逐项确认或已有功能。
> 本地代码核查分支：`codex/three-system-product`。本次只核查文件，没有读取业务库或证明生产状态。
> v0.2 更新：在 v0.1 公共费用分摊基础上，补充全量支出范围、付款与成本双视图、直接归属、工资／奖励／项目／采购来源接入、去重调节和月度完整性核对。

## 1. 业务归属与范围

- 功能放在“财务与管理核算系统”，统一查看公司各类支出来源、实际付款、当期成本及部门承担金额。
- 公司支出可以独立存在，不要求选择项目。已有业务通过来源关联纳入统一台账；库存、项目、奖励等原单据仍由原模块维护，统一查询不重新批准原业务。
- 归属方式分为“部门直接承担”“公共费用按部门系数分摊”“公司留存”。尚未明确归属的金额单列待归属；公司留存是明确选择，不能用来自动掩盖缺失数据。
- 部门系数只分配需要共同承担的当期成本；部门专属费用直接计入该部门，系数不用于重新分摊所有采购款、工资和付款。
- 新分摊结果止于部门。项目来源保留项目标识，新增部门归属作为另一分析维度，不回写既有项目利润、项目预算或负责人管理费。跨部门项目须显式指定承担部门或经确认的分配明细，不能根据项目负责人的当前部门推断全部费用归属。
- 统一报表区分实际成本与内部管理计价。人员、奖励、采购等来源未接齐时显示覆盖范围和缺口，不能标为已完整核算的公司／部门总成本。
- 部门视图命名为“部门成本与费用”，显示本次覆盖类别及待归属金额；本轮没有定义完整部门收入，不能据此显示部门利润。公司利润也必须在收入与成本范围、币种和口径一致后才可形成。
- 周期模板生成计划或待确认记录；费用确认、部门归属／分摊确认、付款记录和对账状态分别保存。统一登记和来源接入不等于建设完整工资计算、总账、银行支付或资产系统。

### 1.1 支出覆盖与来源

以下为目标接入范围，表中的待补能力均不表示已经实现。费用类别可维护、停用并保留历史，自定义类别也必须选择资金性质、期间处理和归属方式。

| 内容 | 统一登记／接入方式 | 成本与部门处理 | 当前衔接边界 |
|---|---|---|---|
| 房租、水电、保洁、物业、公共网络 | 公司支出单据及周期模板 | 先确认所属月份，再按部门系数分摊 | 新增公司独立入口 |
| 部门专用软件、办公用品、差旅、报销 | 手工登记或导入已确认来源，附凭证 | 专属费用直接归属部门；共用部分另行明确分摊 | 新增通用入口，报销凭证与原费用关联 |
| 工资、单位承担的社保等 | 接入或导入已确认工资单／费用来源和实际付款，不用内部费率伪造实际工资 | 保存所属期间及任职／承担部门快照；应发、代扣、实发和单位承担部分分别记录 | 完整实际工资与结算来源待接入；本设计不承诺自动算薪 |
| 奖金、项目负责人管理费 | 引用原已确认成本、个人分配及专用付款记录 | 同一奖励成本只计一次；部门归属保留人员／项目来源 | 已有独立奖金实付和管理费付款登记，统一接入与对账待补 |
| 项目投放、外包、物流、佣金等 | 引用现有项目经营事实，不复制成新公司费用 | 保留项目成本，同时显式记录部门归属；无映射则待归属 | 已有项目成本，实际付款须有对应证据，不能从成本金额推断 |
| 珠宝等商品采购 | 引用采购与库存单据，另关联采购付款 | 采购入库、库存资产与售出成本分别保留；售出成本沿用原快照，付款不再扣一次成本 | 珠宝已有库存与成本，第一阶段未含完整应付／付款，需补来源接入 |
| 设备、长期使用资产 | 登记购置付款并关联经确认的资产处理来源 | 符合资产管理政策时按折旧等规则确认各期成本，再直接归属或分摊；不默认整笔购置款为当期费用 | 完整资产与折旧来源待接入，可先导入已确认结果 |
| 预付房租、预付软件服务等 | 登记实际付款与服务起止期间 | 按受益期间形成月度成本；付款和各期成本不能相加 | 新增跨期费用计划与已确认期间明细 |
| 税费、其他经营费用 | 登记经确认的类别、金额、期间及付款来源 | 按费用、待结算款等实际性质处理，不能将代扣代缴等全部统一视为公司新增费用 | 类别和政策需明确后纳入，未分类列待处理 |
| 押金、借款本金偿还、其他往来 | 记录资金性质、对方、付款及收回／结算关系 | 在资金视图单列，不能自动进入当期成本或公共费用分摊 | 通用资金记录与分类待补 |
| 自有账户之间转账 | 关联同一公司转出、转入记录 | 单列内部转账，不计公司对外支出；未匹配转入保留待核对 | 不把银行流水每一笔借方都当作经营费用 |

### 1.2 实际付款与当期成本

| 视图 | 回答的问题 | 统计依据 |
|---|---|---|
| 实际付款 | 所选期间公司实际付出去多少钱、付给谁 | 已登记有效付款按实际日期汇总；保留凭证与对账状态，草稿／计划／仅费用确认不算实付 |
| 当期成本 | 所选期间经营实际承担多少成本 | 按来源政策已确认、归属该期间的成本；已确认但未支付的费用仍可计入 |
| 部门成本与费用 | 各部门承担多少、来自哪些业务 | 实际成本的直接归属和有效公共分摊；金额不再加回公司成本 |
| 内部管理计价参考 | 按内部费率衡量的项目投入是多少 | 现有内部人工及对应项目管理结果，明确与实际工资口径区别 |

示例：假设 9 月实际预付 9—次年 2 月房租共 60,000 元，按六个完整月份平均确认，则 9 月实际付款 60,000 元、9 月成本 10,000 元，10 月该笔付款为 0、该月成本仍为 10,000 元。每月按当月有效系数分摊 10,000 元，不能对预付总额每月重复分摊。

实际付款视图分别列对外付款、收回退款和净额，退款按实际收回日期记录并关联原付款。跨期退款或退货导致的成本变化由关联调整决定，不随现金收回直接冲减所有当期成本。成本视图记录未支付／部分支付／已支付关联情况，但不依付款状态决定费用所属月份。

费用可以先于付款确认，付款也可以先于成本确认。分批付款、一笔付款结算多张来源、一张来源由多笔付款结清均通过结算关联处理，结算金额不得重复占用。支付币种不同的情况须保留双方原币和经确认的换算记录，缺换算依据列待核对。

员工代付先形成费用与待报销来源，公司报销才形成公司的实际付款；员工代付记录和公司报销不能同时当作两笔公司对外付款。实际付款来源包括经核对的银行、支付平台、公司现金及手工凭证，接入来源和覆盖账户清单须明确。

## 2. 部门系数与计算

对于归属方式为“公共费用按部门系数分摊”的已确认当期成本，每家公司可按费用类别设置一组部门系数。例如房租、用电、用水、保洁可以采用不同系数。设置生效月份，月度分摊预览引用适用版本。直接归属、公司留存与待归属部分不进入系数分母；一笔来源混合多种归属时先明确各部分金额，合计须与来源一致。

```text
部门占比 = 该部门系数 ÷ 本次参与分摊的全部部门系数之和
部门承担金额 = 当月该笔费用应分摊金额 × 部门占比
```

示例为假设数据，部门名称不表示现有组织档案：

| 部门 | 系数 | 计算占比 | 本月房租 12,000 元的承担金额 |
|---|---:|---:|---:|
| 直播运营部 | 3 | 50% | 6,000 |
| 技术部 | 2 | 33.333…% | 4,000 |
| 行政部 | 1 | 16.666…% | 2,000 |
| 合计 | 6 | 100% | 12,000 |

设计约束：

1. 系数使用非负小数，建议最多四位小数；负数、非数值、超范围值拒绝。空值表示未配置，不能自动变为零。
2. 系数不要求合计为 100，也不要求为 1；所有系数同比放大或缩小时分摊金额保持一致。
3. 系数为 0 表示该部门本次明确不承担；至少一个部门系数大于 0 才能确认分摊。
4. 每笔费用可以选择参与部门，仅选中且已配置的部门进入分母；不得静默把未选部门加入平均分摊。
5. 同一次分摊中，同一部门只出现一次；父部门与其子部门不同时作为接收对象，避免口径重叠。建议选择实际承担费用的业务部门，上级按下级结果汇总。
6. 计算使用高精度十进制，不使用浮点金额；按币种规定的金额精度处理尾差。建议采用最大余数法，余数相同时按稳定部门 ID 顺序处理，保证相同输入得到相同结果。
7. 计算过程使用原系数，不使用界面已四舍五入的占比；界面提示占比为展示值。每笔原费用的部门分摊金额合计必须严格等于应分摊金额。

## 3. 月度办理与历史

成本办理流程：登记或引用来源 → 确认当期成本及归属方式 → 直接归属部门／公共费用分摊预览／明确公司留存 → 核对确认。

付款办理流程独立进行：引用已有实付或登记实际付款 → 关联待结算来源 → 核对付款凭证和账户流水。实际付款尚未匹配业务来源时，保留资金事实并标记待匹配，不凭空生成一笔成本。

| 操作 | 建议行为 |
|---|---|
| 维护长期系数 | 按公司、费用类别设置部门系数和生效月份；同一月份不能同时匹配多组有效规则 |
| 生成月度预览 | 显示来源费用、所属月份、币种、部门、系数、占比和分摊金额；缺规则时提示待配置 |
| 仅调整本次 | 在未确认预览中修改系数并填写原因，只影响本次分摊，不修改以后月份的模板 |
| 调整以后月份 | 保存有明确生效月份的新规则版本；已存在预览显示规则已更新，显式重新生成后再确认 |
| 确认费用 | 已确认的当月成本按唯一来源进入公司对应口径统计；公共分摊未完成、部门未归属或尚未支付时均保留金额并显示待办 |
| 直接归属 | 选择一个明确承担部门；混合归属按来源行或经确认明细拆分，保留金额和组织快照；不套用公共系数 |
| 确认分摊 | 保存来源版本、系数、金额、部门名称及所属公司快照、操作人和确认时间；重复提交不得生成第二份有效结果 |
| 已确认后更正 | 通过关联冲销／更正保留旧结果，再确认新结果；不覆盖原单或随模板修改静默重算 |
| 组织变更 | 部门更名、停用、迁移后，已确认历史使用快照；新预览按有效组织关系校验，确认时再次校验 |

部门月中新增、合并或使用情况改变时，可以对当月系数进行有原因的调整。第一版不自动推断人数、面积或在岗天数，也不以当前组织结构倒算过去月份。

费用所属月份独立于付款日期。预付费用先形成各月成本计划，各期确认后逐月按当月部门系数分摊。付款记录关联业务来源，不再次增加成本。月度费用状态不复用项目交付或项目关账状态；引用已关闭项目的合法成本和付款保持原来源办理规则。

未来月份的周期模板和预计金额列入计划视图；已确认费用与暂估、草稿及未收到的账单分别显示。若增加期间锁定，应独立于项目关账校验，锁定期间的更正保留来源和调整期间。

## 4. 页面与数据对象建议

财务系统内提供“公司支出与成本”入口，下设统一台账、实际付款、部门系数、月度归属与分摊、成本报表及对账待办。台账按来源域、资金性质、费用类别、部门、期间、币种及状态查询。现有项目收支、奖金和管理费页面继续维护原业务，统一入口按权限下钻到来源。具体页面拆分在编码时按现有导航模式落实。

| 逻辑对象 | 保存的主要信息 |
|---|---|
| 支出来源与统一索引 | 公司、来源域、来源单号／行号、资金性质、类别、金额币种、覆盖期间、对方、附件、版本及更正关系；区分新登记来源与已存在来源的引用 |
| 期间成本明细 | 来源、所属期间、确认金额、成本口径、来源政策及版本；保留内部计价／实际来源／调节关系，不将付款直接转换为成本 |
| 部门直接归属 | 来源成本、部门及公司快照、归属金额、确认身份、来源版本及更正关系 |
| 部门系数规则及明细 | 公司、费用类别、生效月份、版本；参与部门及各自系数 |
| 月度分摊及明细 | 来源月度费用、规则版本、本次系数快照、归属部门、占比、金额、状态及调整原因 |
| 付款与结算关联 | 独立付款来源、资金账户、实际日期、金额币种、对方、凭证、登记人；每笔付款与多个业务来源的结算金额、汇率依据、退款／更正关系及待匹配余额 |
| 来源覆盖与对账记录 | 公司、期间、来源域及账户覆盖、导入批次、最后同步时间、缺失／差异／重复候选、未匹配余额、处理人和对账结论 |

以上为逻辑对象，不是已存在的表名、API 或迁移编号。实施时复用既有附件、审计和状态处理模式，不通过给项目事实强塞虚拟项目承载公司费用。

公司成本视图按唯一的当期成本来源及有效调整汇总，部门视图按直接归属与有效分摊汇总；两者不能相加。相同公司、期间、币种、口径和授权范围下必须满足：

```text
公司当期成本 = 部门直接归属合计 + 部门公共分摊合计 + 明确公司留存 + 待归属／待分摊金额
```

待归属与待分摊按不重叠状态计数。同一来源各部分金额只进入上式一项。父部门展示的汇总行不是额外成本明细；汇总全部部门时只累计原归属明细一次。

### 4.1 人工与重复来源的处理

- 现有项目内部人工成本继续保留在内部管理计价视图。公司实际成本采用实际工资等经确认来源，不能将包含内部人工的项目利润直接再减全额工资。
- 若从已有项目汇总衔接公司实际经营结果，应显式列出“已包含的内部人工”“实际人员成本”及其他调节项，以可追溯调节桥接到实际口径；未能剥离内部人工或缺真实工资时，不发布完整实际成本／利润。相同奖励已在工资来源中出现时，也必须关联到原奖励并消除重复。
- 统一来源身份至少包含公司、来源域、单号／行号及经济事件标识；导入、手工录入和重试不能因来源通道或版本不同而创建同一事件的第二份有效成本。
- 成本与付款分别去重。每笔实际付款有唯一资金来源身份，结算关联只解释付款用途，不增加付款总额；银行流水与奖金实付等已登记记录匹配后引用同一付款。
- 原系统中的采购金额、销售成本、奖励核准、奖励成本、分配及实付代表不同事件，不能只按金额和日期相同就自动合并；疑似重复列入人工核对。

### 4.2 完整性与月度对账

每家公司设置目标来源清单，包括工资及单位承担费用、奖励、各业务模块、公司费用、各付款账户和现金来源。各来源按月份标记“已接入并核对”“部分覆盖”“未接入”“本期无业务且已确认”。无记录不能自动等同本期为零。

月度待办至少包含：费用账单未收到、工资未接齐、待分类／待计价、待归属／待分摊、付款未匹配、疑似重复、退款与源单差异、库存成本或资产处理来源缺失、同步失败／陈旧。

资金核对将已登记付款与银行、支付平台、现金等证据对齐；成本核对检查各域来源及期间确认结果，不能仅凭银行付款全部匹配就断言成本完整。报表同时标出统计期间、币种、成本口径、来源覆盖和对账时间。仅在所需来源覆盖完整、关键差异处理完毕且授权范围完整时，才显示对应口径的“本期已核对”；否则显示已知金额及缺口。

不同币种分别展示；没有经过确认的换算政策和汇率时不合并金额。月度报表不把月度费用一次扣在老板昨日经营回顾中；若需要日度视图，须另行定义按日归属政策。

## 5. 现有实现衔接与权限

已核查的本地代码事实：

- [经营事实建表](../backend/sql/migrations/V023__business_daily_accounting.sql)中 `biz_operating_fact.project_id` 非空；[现有核算服务](../backend/ruoyi-system/src/main/java/com/ruoyi/business/service/impl/BusinessAccountingServiceImpl.java)录入时强制选择项目。因此公司费用需要独立的来源和办理入口。
- [现有核算 Mapper](../backend/ruoyi-system/src/main/resources/mapper/business/BusinessAccountingMapper.xml)按项目日结果汇总公司金额；既有 `ADMIN_ALLOCATION` 分类已经进入项目成本，不能把已有费用再直接复制成公司新增成本。
- [内部人工计价实施记录](./P2-资源投入与成本计价实施记录.md)明确内部费率及已确认工作计价，未记录／待计价保留未知；它不是完整实际工资和支付来源。
- [奖金分配与发放实施记录](./奖金分配与发放实施记录.md)说明已于 2026-09-09 本地实现独立奖金实付；[奖金分配 Mapper](../backend/ruoyi-system/src/main/resources/mapper/business/BusinessBonusDistributionMapper.xml)已有 `biz_bonus_payment` 查询和写入。[管理费服务](../backend/ruoyi-system/src/main/java/com/ruoyi/business/service/impl/BusinessProjectManagementFeeService.java)也有专用付款登记。统一模块应引用这些来源，不能写成原系统完全没有付款功能，或从奖励核准金额推断实付。
- [珠宝 ERP 设计](./珠宝ERP-第一阶段需求设计.md)规定采购入库更新库存平均成本、销售保存出库成本快照，第一阶段不含应付／付款／总账。采购单不是付款证据；统一视图继续沿用珠宝单据审批、库存和红冲规则。
- [直播统计口径](./统计口径说明.md)仍以主播日报维护 Xu 流水；本轮不改变该指标，也不将未经确认结算与换算的 Xu 流水直接当成公司现金收入。
- 公司和部门可引用 `sys_dept` 的稳定 ID 及组织关系。公司目录查询和项目归属老板筛选是两类现有规则，目录可见不代表公司费用可见，也不代表有权维护部门系数。

建议权限边界：

- 来源登记、付款查看／登记、系数维护和归属／分摊确认各有功能权限，并与明确授权的公司范围取交集；本公司有效业务部门属于候选范围，公司与集团节点不作为部门接收方，不允许跨公司分摊。
- 部门查看权限明确到部门及是否包括下级；普通部门用户只查看获授权部门的已确认金额，不因组织目录权限获得其他部门或公司全量明细。工资、奖金个人明细和付款账户信息须额外字段授权，能看部门汇总不等于能看每个人的工资。
- 费用登记者、财务复核者、分摊确认者保留操作身份，默认创建与最终复核分离；技术管理员管理配置不自动取得业务批准权。
- 新模块不得直接沿用“能看某个老板的项目就能看整家公司费用”的逻辑；实施前明确公司负责人和财务角色的授权映射，并验证两位老板、跨公司、部门负责人、录入人、复核人和管理员。
- 统一台账采用经明确授权的跨域汇总或引用接口，不因接入而放宽原项目、奖金、珠宝等明细权限；公司完整报表不能从当前用户有权看到的部分项目简单拼装。奖金原付款不可覆盖等限制继续生效，通用退款／更正设计不自动给原奖金模块增加退款或删除能力。
- 来源登记、费用确认、付款及分摊操作须在服务端、导出及任何后续 AI／批量入口中采用一致权限和状态规则。

历史费用衔接：新模块上线前明确各来源起算月份、历史已付／未付及预付余额。至少核对一笔真实来源与既有 `ADMIN_ALLOCATION`／其他项目费用的关系，每个实际接入的金额来源也需有真实样本核对。历史已在项目扣除的来源保持原结果；若迁入新模块，必须建立唯一来源映射和必要的公司视图调节。公司新报表须采用范围一致、去重后的成本及人工口径调节，不把某位老板的部分项目利润减去全公司的费用后标为公司利润。

## 6. 实施验收清单

- 系数 3、2、1 分摊 12,000 元得到 6,000、4,000、2,000；等比改为 6、4、2 结果一致。
- 负数、空值、全部为零、重复部门、跨公司部门、父子部门同时选中均按上述规则处理；零系数与未配置状态清晰区分。
- 小金额、循环小数及不同币种精度下，尾差可解释且分摊金额严格守恒。
- 房租与电费使用不同系数；本次调整和以后月份规则变更互不混淆。
- 重复提交及并发确认只形成一组有效分摊；来源金额或规则变动后，旧预览不能未经核对直接确认。
- 更正、取消、部门更名／迁移保留历史链；费用确认而分摊待办时公司金额不丢失。
- 公司总额不重复加上部门分摊；项目利润、预算、奖金及负责人管理费不受本模块分摊影响。
- 付款、费用确认、部门分摊分别可核对；草稿和计划金额不冒充已确认费用；月度结果不混入未定义归属的单日统计。
- 部门专属费用直接归属，公共费用按系数，公司留存与待归属单列；跨部门项目无明确映射时保留待办，不根据负责人当前部门自动归属。
- 半年房租实付 60,000 元、各月成本 10,000 元；未付款已确认费用可进入当期成本，付款未匹配来源时只保留资金事实。
- 项目内部人工与实际工资分开并通过明确口径调节；工资中已有奖金关联到原奖励。缺工资或无法去除重复人工时不声称实际成本完整。
- 已有奖金／管理费付款导入、银行流水匹配和重复请求不新增第二笔付款；分批和合并结算金额可核对，保留原模块权限与更正限制。
- 商品采购付款、库存资产、售出成本分别核对；设备购置与折旧、预付与摊销按有效来源和期间处理，不能把全额付款再作为当期成本。
- 员工代付与公司报销只产生一次公司对外付款；退款单列并关联源单，自有账户转账不计对外支出，往来性质不自动变成经营费用。
- 不同币种与来源口径分列；费用确认、付款核对和来源完整性分别显示，缺来源、同步失败及待匹配不能显示为零或已完整核算。
- 权限覆盖创建人、复核人、管理员、部门负责人、不同公司和项目归属老板；同样验证接口与导出。
- 改动金额统计 SQL 前先核对真实样本，再运行聚焦后端测试；前端改动运行 `pnpm run build:prod`，影响双语页时检查中文与越南语。
