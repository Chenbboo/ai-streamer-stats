> 实施更新（2026-09-07）：P1–P4 首轮代码、菜单与迁移已本地实现，V063–V067 已在本地验证应用。当前交接与验收以 [P1–P4 总记录](./P1-P4-三系统实施与验收记录.md) 为准；真实飞书授权/六类样本与生产部署尚未完成。
> 下方代码行号、“当前证据”和差距正文保留为改造前盘点；后续改动使部分行号及行为失效，不能据其断言现在仍缺少已实现功能。
> 核对基线：本地 `codex/system-baseline`。单平台三个业务系统的内部版本，不代表服务器已部署或跨客户标准产品验证完成。
> 范围：统一平台下的项目管理系统、人力资源管理系统、财务与管理核算系统及共享能力；直播与珠宝仅验证兼容，不在本轮改写行业业务。
> 本次修订：统一三系统下级菜单及 KPI、绩效、奖励和支付的归属，P1—P4 与后续范围不扩展；先看[三系统拆分方案：审阅版](./三系统拆分方案-审阅版.md)。

### 改造前判定与保留原则

已经审读总体设计、立项设计、项目 KPI 与奖金设计、交接基线、统计口径和珠宝 ERP 设计，并以当前服务、SQL 和页面校正历史文档。

- **新立项已由负责人自主启动。** `BusinessProjectProposalServiceImpl.java:144–159` 直接建项并记录 `OWNER_LAUNCH`；`V057__owner_driven_project_business_plan.sql:105–110` 将老板审批入口标为历史处理。不能把全部项目描述成仍需老板批准立项。
- **新 KPI 提交已由负责人直接确认。** `BusinessProjectKpiServiceImpl.java:218–243` 提交、确认并生成奖金成本；`:249–280` 仍保留旧 `SUBMITTED` 的老板审核路径。历史设计中的“全部由老板确认”不适用于当前所有记录。
- **逐人人工成本快照已有实现。** `BusinessAccountingServiceImpl.java:402–416、447–450` 保存并读取日结果明细；不把旧交接文档中的“尚未实现快照”继续当成现状。仍需补齐结构化计算依据与更正策略。
- **待改的是业务耦合。** 项目关闭同时检查 KPI、投入、请假及收支，再关账；不能只移走菜单或删除一条校验。

原则：增量表/字段和接口兼容优先；流程版本在对象创建或明确迁移时固定，不能由全局开关随意改变在办单据语义；保留旧状态、审计、金额和来源，不把百分比历史倒算成已确认工时。

`deliveryPolicyVersion`、`accountingState`、`settlementPolicyVersion` 已在本轮落实，成本与奖励另分别使用 `costPolicyVersion`、`rewardPolicyVersion`。项目业务状态表达执行与交付，项目核算 `OPEN/CLOSED` 表达是否接受后续结算；它不等于企业会计期间的 `OPEN/LOCKED`。企业期间管理仍为后续范围。

## 3. 可执行差距清单

### GAP-01｜固定流程版本与现状基线

- **证据：** S2:144、182；S3:218、249；M3:1、105。新旧立项、结算路径共存，历史文档未完整同步。
- **处理 / 目标：** 重构；为交付策略、结算确认策略、成本方法分别建立版本/来源标识与状态映射，不以“旧数据”一个布尔值概括全部历史。
- **依赖：** 无；属于 P1 前置迁移。
- **完成条件：** 输出按状态和来源分组的只读盘点及迁移预演；无法判定确认策略的记录进异常清单，继续原路径；重复迁移不重复改写，历史审批人和金额不变。

### GAP-02｜项目交付与后续结算分离

- **证据：** S1:861–866、1031–1052、2271–2284、2446–2485；关闭依赖 KPI、请假、投入和收支，并调用关账。
- **处理 / 目标：** 重构；新策略项目按任务、成果及所选验收方式完成交付，KPI/费用/资源待确认转为独立后续事项；交付完成仍冻结执行计划及任务。
- **依赖：** GAP-01、03、16、17 必须同批上线，不能单独去除关闭校验。
- **完成条件：** 直接结项、成果验收、阶段验收三条路径一致；无 KPI、周期未结束及有未结费用均可完成合格交付，并显示准确后续事项；取消单独处理，不视作成功交付。

### GAP-03｜独立核算状态与交付后结算兼容

- **证据：** S3:181、223、620–623 仅允许执行/验收期结算；S4:357–369、385、494–499 把项目关闭视作关账。
- **处理 / 目标：** 重构 / 新增；建立独立项目核算状态与关账动作，交付完成且项目核算开放时仍允许原有 KPI 结算、费用确认/冲正和必要重算，真正关账后通过受控调整处理；若期间锁定能力已启用，另受其约束。
- **依赖：** GAP-01、02；同批检查后台校验、列表筛选、页面可操作判断及日结果查询。
- **完成条件：** `DRAFT/RETURNED/SUBMITTED/CONFIRMED` 各类旧结算都有明确续办路径；新负责人确认和旧审核人确认均可在交付后完成；幂等键不变且奖金只记一次；已关闭历史账不批量重开。

### GAP-04｜通用项目启动与立项模板

- **证据：** S2:151、408–422 强制具体人员月成本、成本币种一致和预算上限；S2:154–159 已是自主启动。
- **处理 / 目标：** 重构；项目模板声明必需资料、启动权限及是否审批，基础模板允许目标、负责人、计划和交付标准齐备后启动，预算/薪酬资料按启用能力要求。
- **依赖：** GAP-01、16；P2 实施，不恢复写死的“所有项目老板审批”。
- **完成条件：** 基础项目无奖金及个人成本原值也能启动；启用预算控制的模板有独立校验；模板版本冻结，历史 `PENDING` 不被重复建项或静默自批。

### GAP-05｜项目核心计划、成果与变更

- **证据：** S1:2243–2255 已校验任务父子关系；S1:2287–2305、2422–2424 已有任务、里程碑和成果校验。
- **处理 / 目标：** 保留 / 重构 / 新增；保留任务、成员、里程碑、风险、验收，补明确的范围/计划基线和变更记录；工作台围绕待办、延期、风险与成果。

- **完成条件：** 一个标准示例完成创建、任务分派、计划调整、进度提交、风险处理和验收；历史基线可追溯，交付后不能借编辑接口继续增加执行任务。

### GAP-06｜工作日历、单位与人员资源计划

- **证据：** S2:315、348–361 按整个项目日期和每人 100% 估算；S1:707 检查比例占用；Q1:179 固定按 8 小时换算。
- **处理 / 目标：** 重构 / 新增；分别记录工期、人员参与区间、计划工作量、容量比例；工作日历计算可用容量，独立版本化单位政策确定分钟/人天，分别保存快照；比例保留为资源安排能力。
- **依赖：** GAP-04、05、13；P2。
- **完成条件：** 同一项目两人参与不同日期且工作量不同可正确排期；假日、半天、跨项目超配给出明确结果；6 小时工作日只改变可用容量，不自动改变 1 人天的换算定义；变更日历或单位政策均不重写既有快照。

### GAP-07｜独立实际工作量及更正

- **完成条件：** 未填报显示“未记录”，不能当成零投入或已确认计划；跨项目重复/超容量有校验和授权例外；确认后更正保留前版本，关闭期间不能直接改成本。

- **依赖：** GAP-03、06、07、13；改变 SQL 前必须核对一个真实样本，不能只使用模拟数据声称对账通过。
- **完成条件：** 原始记录、逐人金额与项目汇总可追溯并一致；缺费率显示缺失不冒充零成本；飞书请假不直接归零，公司用人成本与项目归集清楚分开。

完整员工绩效、个人奖金分配/发薪反馈及企业会计期间管理按后续产品版本排期；本轮定义其对象与接入边界，不以空白菜单宣称已经交付。P1 项目级独立关账不能包装成完整会计期间管理。

**P1 最小闭环的边界：** 不在首批同时建设完整绩效或薪酬，也不依赖飞书授权。保留现有 KPI+奖金计算作为版本化旧联动，但在新交付策略下允许交付后完成；明确提示其业务含义，不能把旧池当作已发薪。首批必须同时改项目关闭、KPI 结算、核算开放判断、页面状态及权限，不能分开发布半套状态逻辑。

P1 验收至少覆盖：无 KPI 项目、未到期 KPI、已到期草稿、被退回结果、历史待老板审核、已确认奖金、待确认费用、重复关闭/结算、已关账历史项目以及取消项目。关闭执行资源应保留有效日期和历史计划；交付后只允许补录交付前已发生且授权的事实，不重新开启任务执行。
