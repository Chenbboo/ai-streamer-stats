# 珠宝ERP第一阶段需求设计

## 1. 文档目的

本文档定义 meimaru 管理系统中“珠宝ERP”第一阶段的功能范围、角色权限、业务流程、库存规则、成本规则和数据结构建议。

本文档作为后续页面设计、数据库设计、接口开发和验收测试的统一基线。未写入本阶段范围的功能，不在第一阶段实现。

## 2. 产品定位

珠宝ERP是现有系统中的独立业务板块，与“直播数据管理”并列。

珠宝ERP与直播数据管理只共用系统登录底座，不共用业务人员、业务角色或业务数据。

第一阶段定位为：

- 单仓库珠宝进销存
- 同一SKU管理多件商品
- 单据驱动库存
- 普通业务单据单级审核，库存调整单和库存成本调价单双级审核后入账
- 移动加权平均成本
- 销售毛利与亏损风险控制

## 3. 第一阶段菜单

```text
珠宝ERP
├─ 人员管理
├─ ERP概览
├─ 商品档案
├─ 供应商档案
├─ 库存台账
├─ 库存盘点
├─ 单据管理
├─ 审批中心
└─ 毛利试算
```

“珠宝ERP”是根级目录，不属于“直播数据管理”。

## 4. 人员与权限

### 4.1 人员隔离

- 单独建立珠宝ERP人员关系表。
- ERP人员页面不读取主播列表。
- 直播角色不会自动获得ERP菜单或数据权限。
- ERP角色不会自动获得直播业务权限。
- 珠宝ERP菜单不得继承“数据统计”或任何直播角色的权限。
- 底层可以关联现有 `sys_user` 登录账号，但ERP业务身份独立维护。
- ERP人员停用后不能继续制单或审核，历史记录必须保留。
- 菜单、接口和前端组件统一使用 `jewelry` 命名空间，不得放在 `live` 命名空间中。
- ERP角色以若依 `sys_role` 和 `sys_user_role` 为唯一权限来源，`jewelry_staff` 不重复保存角色字段。

### 4.2 ERP角色

| 角色 | 角色编码 | 职责 |
|---|---|---|
| 制单员 | `jewelry_maker` | 创建采购、出库、退货、盘点等业务单据 |
| 审核员 | `jewelry_reviewer` | 审核普通业务单据；对库存调整单和库存成本调价单执行初审 |
| 管理员 | `jewelry_admin` | 管理ERP人员、商品、供应商和全部ERP数据；对库存调整单和库存成本调价单执行最终复核 |

每位ERP人员第一阶段只分配一个ERP角色。

系统至少需要一名制单人员、一名不同的审核人员和一名管理员，才能完成库存调整或库存成本调价单的完整流程。

### 4.3 权限矩阵

| 功能 | 制单员 | 审核员 | 管理员 |
|---|---:|---:|---:|
| 查看ERP概览 | 是 | 是 | 是 |
| 查看商品、供应商 | 是 | 是 | 是 |
| 新增商品 | 是 | 否 | 是 |
| 修改商品名称和图片 | 是 | 否 | 是 |
| 修改商品其他资料、管理供应商 | 否 | 否 | 是 |
| 查看库存台账与流水 | 是 | 是 | 是 |
| 新建、编辑草稿单据 | 是 | 否 | 是 |
| 提交单据 | 是 | 否 | 是 |
| 审核通过或驳回 | 否 | 是 | 是 |
| ERP人员管理 | 否 | 否 | 是 |
| 商品、供应商导入导出 | 否 | 否 | 是 |
| 业务数据导出 | 按权限 | 按权限 | 是 |

数据查看范围：

- 制单员查看自己创建的全部单据。
- 审核员查看所有待审、已审和已入账单据，但不能修改单据内容。
- 管理员查看全部ERP数据。

### 4.4 强制审批限制

- 制单人不能审核自己创建的单据。
- 管理员同样不能审核自己创建的单据。
- 普通业务单据只需一名具有审核权限的人员审核一次。
- 库存调整单和库存成本调价单必须先由审核员初审，再由管理员复核；两次审批通过后才允许改变库存或平均成本。
- 调价单制单人、初审人和最终复核人不得是同一账号；初审与复核也不得由同一账号完成。
- 审批身份必须使用登录账号ID判断，不能依靠手工填写姓名。
- 并发审批时只接受第一个符合当前状态的操作。

## 5. 基础档案

### 5.1 ERP人员

建议字段：

- ERP人员ID
- 登录账号ID
- 员工编号
- 姓名
- 联系电话
- 启用状态
- 加入时间
- 最近操作时间
- 备注

页面展示的ERP角色通过登录账号关联 `sys_user_role` 和 `sys_role` 查询，不在人员表中维护第二份角色值。

### 5.2 商品档案

商品按普通SKU数量管理，不做一物一码。

| 字段 | 规则 |
|---|---|
| SKU编码 | 全局唯一，必填 |
| 商品名称 | 必填 |
| 商品类型 | 成品商品、散件商品、配件商品、福利商品，四选一 |
| 商品分类 | 戒指、项链、耳饰等 |
| 规格类型 | 精品、普通，二选一 |
| 商品主图 | 单张主图 |
| 计量单位 | 默认“件” |
| 当前平均成本 | 系统计算，只读 |
| 默认包装费 | 非负金额 |
| 默认物流费 | 非负金额 |
| 默认鉴定费 | 非负金额 |
| 库存预警值 | 默认5 |
| 状态 | 启用、停用 |
| 备注 | 选填 |

已经产生库存或历史单据的SKU不能删除，只能停用。

只有从未使用且所有库存数量均为零的SKU允许删除。

商品档案不维护固定采购价。实际采购价在采购入库单中填写，当前平均成本由系统计算。

制单员可以直接修改已有商品的商品名称和实物图片，无需审批；SKU、商品类型、分类、规格类型、单位、默认费用、库存预警值、状态和备注仍仅允许ERP管理员修改。后端必须使用受限更新语句保证制单员不能通过接口修改其他字段。

### 5.3 供应商档案

建议字段：

- 供应商编码
- 供应商名称
- 联系人
- 联系电话
- 地址
- 结算方式
- 启用状态
- 备注

业务规则：

- 仅ERP管理员可以新增、修改和停用供应商。
- 采购入库和供应商退货必须选择已启用供应商。
- 供应商停用后不能用于新单据。
- 历史单据保留供应商ID和名称快照。

### 5.4 销售渠道

第一阶段不建立普通客户档案，但建立“达人/主播库”。达人编码由系统在新增后按 `DR + 6位流水ID` 自动生成（例如 `DR000001`），不可人工填写或修改；达人ID用于记录平台侧的达人标识，由用户维护且暂不强制填写。达人档案维护名称、平台、平台账号、默认销售渠道和状态，并关联该达人名下多个商品的固定成交单价。

固定成交单价按“达人/主播 + 商品SKU”分别维护。同一达人可以关联多个商品，每个商品各有自己的价格、状态和版本。制单员在销售出库单选择达人后：已定价商品自动带入并锁定固定价；未定价商品由制单员填写成交单价，保存草稿时立即在达人库形成“待生效”商品价格，单据最终审核入账后转为正式固定价。其他销售单不得重复占用同一达人同一商品的待生效价格。草稿删除或单据驳回时清除该单创建的待生效价格，撤回到草稿则保留。

销售出库单存在销售组合时，审核入账后还要按“达人/主播 + 主商品 + 搭售散件”保存搭售绑定关系，并记录主商品数量、散件数量、计价方式和最近来源单据。包含在组合价中的散件只建立搭售关系，不建立虚假的固定成交价；达人库可以分别查看商品固定价和已绑定搭售散件。

管理员只能修改已经正式生效的达人商品价格，必须填写原因并形成按SKU记录的价格历史。销售和退货单明细保存商品固定价及版本快照，历史单据不受后续改价影响。包含在组合价中的搭售商品成交价为0，不建立达人商品固定价；单独计价的搭售商品按自身SKU建立固定价。

## 6. 库存模型

第一阶段只管理一个仓库，不提供仓库、库位和调拨功能。

每个SKU至少维护以下库存量：

- 账面总库存：已经正式入账、仍归企业所有的全部商品数量，包括可售库存、售后待检和次品库存。
- 可售库存：已经正式入账且可以销售的商品数量。
- 出库待审冻结：已经提交销售出库、供应商退货或盘亏调整，但尚未审核的数量。
- 可用库存：可售库存减去出库待审冻结。
- 售后待检：消费者退货后，尚未完成质检的数量。
- 待检处理冻结：已经提交质检处理单，但尚未审核的待检数量。
- 可处理待检：售后待检减去待检处理冻结。
- 次品库存：质检后不可重新销售的数量。

```text
账面总库存 = 可售库存 + 售后待检 + 次品库存

可用库存 = 可售库存 - 出库待审冻结

账面总库存 = 可用库存 + 出库待审冻结 + 售后待检 + 次品库存

可处理待检 = 售后待检 - 待检处理冻结
```

台账数字禁止手工修改。所有变化必须来自正式入账的业务单据和库存流水。

冻结规则：

- 销售出库、供应商退货和盘亏调整在提交时冻结对应可售库存。
- 退货质检处理单在提交时冻结对应售后待检数量。
- 撤回或驳回时释放对应冻结。
- 审核通过时，在同一事务中扣减可售或待检数量并释放冻结。
- 提交和审核时都必须使用数据库条件更新再次校验数量，防止并发超卖或重复处理退货。

### 6.1 库存预警

```text
当前可用库存 <= 商品库存预警值
```

满足条件的SKU在ERP概览和库存台账中标记为库存不足。

## 7. 成本与毛利

### 7.1 移动加权平均成本

采购入库正式入账时：

```text
新平均成本 =
（入库前可售库存 × 原平均成本 + 本次入库数量 × 本次采购单价）
÷（入库前可售库存 + 本次入库数量）
```

规则：

- 采购入库审核通过、正式入账时才按移动加权公式更新平均成本。
- 销售出库时保存当时的平均成本快照。
- 后续采购价格变化不能修改历史销售成本和历史毛利。
- 供应商退货按当前平均成本减少库存资产，平均成本不变。
- 消费者退货关联原销售单时，良品退货按原销售成本重新计入库存成本；未关联时使用退货登记时的库存平均成本作为待检成本快照。
- Java后端金额使用 `BigDecimal`，禁止使用浮点数直接记账。
- 单价和平均成本数据库保留6位小数；采购单价、供应商退货单价、未关联原销售单的客户退货实际退款单价、采购金额、采购总额、供应商退货金额和退货总额录入及展示保留4位小数，其他金额展示和单据合计保留2位小数。
- 统一使用 `RoundingMode.HALF_UP`，禁止前后端各自采用不同舍入规则。

### 7.2 销售毛利

每行销售明细计算：

```text
销售收入 = 成交单价 × 数量

商品成本 = 出库成本快照 × 数量

比例费用 = 销售收入 ×（平台扣点率 + 达人佣金率 + 税率）

固定履约费用 =（包装费 + 物流费 + 鉴定费 + 其他1 + 其他2 + 其他3）× 数量

毛利 = 销售收入 - 商品成本 - 比例费用 - 固定履约费用

毛利率 = 毛利 ÷ 销售收入
```

出现负毛利时：

- 制单页面即时红色预警。
- 单据列表显示风险标记。
- 审核通过需要明确确认。
- 第一阶段不完全禁止亏损单入账。

## 8. 单据管理

### 8.1 整表操作

单据采用全宽可编辑表格，不使用逐个SKU弹窗。

页面结构：

- 顶部：单据日期、供应商或销售渠道、外部单号、备注等单据头信息。
- 中部：可连续录入多个SKU的编辑表格。
- 底部：总件数、总金额、总成本、总毛利等合计。
- 操作：新增行、复制行、删除行、Excel粘贴或导入、保存草稿、提交审核。

一张单据可以包含多个SKU。整张单据统一提交、统一审批，不逐行审批。

明细录入规则：

- 数量必须为正整数。
- 金额、费率和费用不能为负数。
- 同一张单据中不允许出现重复SKU；选择重复SKU时提示合并数量。
- 单据提交时后端必须重新计算合计和毛利，不能信任前端传入的计算结果。

### 8.2 单据类型

| 类型 | 作用 |
|---|---|
| 采购入库单 | 增加可售库存（同时增加账面总库存）并重新计算平均成本 |
| 销售出库单 | 冻结并最终扣减库存，记录销售毛利 |
| 供应商退货单 | 将商品退回供应商并扣减库存 |
| 消费者退货登记单 | 将收到的退货转入售后待检 |
| 退货质检处理单 | 将待检数量拆分为良品和次品 |
| 库存盘点调整单 | 处理盘盈、盘亏和库存录入差异 |
| 库存成本调价单 | 不改变库存数量，经双级审批后修改指定SKU的平均成本 |
| 红冲单 | 反向冲销已经正式入账的原单据 |

### 8.3 单据状态

```text
草稿
  ↓ 提交
待审核
  ↓ 审核通过
已入账
```

库存调整单和库存成本调价单使用双级审批状态：`草稿 → 待审核员审核 → 待管理员复核 → 已入账`。

辅助状态：

- 已驳回
- 已红冲

处理规则：

- 草稿可以由制单人本人修改或删除；删除时同步清理草稿明细、审批记录和事件记录，非草稿状态禁止删除。
- 待审核可以由制单人撤回，撤回后回到草稿状态并记录撤回日志。
- 普通单据入账后显示审批人；库存调整单和库存成本调价单同时显示审核员和管理员。
- 驳回时必须填写原因。
- 已驳回单据可以复制为新草稿。
- 已入账单据不能修改或删除。
- 已入账单据发现错误时必须创建红冲单。
- 普通红冲单仍需经过审核员审核；库存调整或库存成本调价单的红冲仍需审核员和管理员双级审批。

### 8.4 红冲规则

第一阶段只支持整单红冲，不支持部分行或部分数量红冲。

- 红冲单必须关联一张已入账原单。
- 同一张原单只能成功红冲一次。
- 原单已经红冲后不能再次红冲。
- 红冲单复制原单全部业务快照，不允许手工修改SKU、数量、成本或金额。
- 红冲审核通过后，原单状态更新为已红冲。
- 红冲前必须重新校验当前库存，不能因为红冲产生负库存或负资产。

各单据红冲处理：

- 采购入库红冲：减少原入库数量和原入库成本金额；要求当前可售库存及库存资产足够扣减，扣减后重新计算平均成本。
- 销售出库红冲：按原出库成本快照恢复库存，并与当前库存重新计算移动平均成本。
- 供应商退货红冲：按原退供成本快照恢复库存并重新计算平均成本。
- 消费者退货登记红冲：减少对应售后待检数量；待检数量已被质检处理时禁止红冲。
- 退货质检处理红冲：良品从可售库存退回待检，次品从次品库存退回待检；相关数量不足时禁止红冲。
- 盘点调整红冲：执行原调整的反向变化，并重新校验库存和成本。
- 库存成本调价红冲：库存数量不变，且当前平均成本仍等于调价后成本时，恢复原平均成本。

### 8.5 单号

单号由系统自动生成，按业务类型、日期和流水号组成。

示例：

```text
RK202607280001  采购入库
CK202607280001  销售出库
TG202607280001  供应商退货
SH202607280001  消费者退货登记
ZJ202607280001  退货质检
PD202607280001  库存盘点调整
TJ202607280001  库存成本调价
HC202607280001  红冲
```

单号必须具备数据库唯一约束。

## 9. 各类单据字段

### 9.1 采购入库单

单据头：

- 入库日期
- 供应商
- 供应商单号，可选
- 经办人
- 备注

明细表：

- SKU
- 商品名称
- 当前可售库存
- 当前平均成本
- 入库数量
- 实际采购单价
- 采购金额
- 入库后的预计平均成本
- 操作

审核通过后增加可售库存（同时增加账面总库存）并更新移动平均成本。

### 9.2 销售出库单

单据头：

- 出库日期
- 销售渠道
- 平台订单号
- 达人/主播，必选
- 平台扣点率
- 达人佣金率
- 税率
- 备注

明细表：

- SKU
- 商品名称
- 当前可用库存
- 出库数量
- 成交单价
- 达人商品固定价和价格版本快照
- 当前平均成本
- 包装费
- 物流费
- 鉴定费
- 其他1
- 其他2
- 其他3
- 单件毛利
- 毛利率
- 合计毛利
- 风险状态
- 操作

提交后冻结对应可售库存。驳回或撤回时释放冻结；审核通过时扣减可售库存（同时扣减账面总库存）。

销售出库支持“成品带搭售商品”的销售组合：

- 成品作为组合主商品，必须是“成品商品”；一个组合必须且只能有一个主商品。
- 主商品下可以添加一个或多个非成品商品作为搭售明细，支持散件商品、配件商品和福利商品，不允许再次选择成品商品。
- 搭售商品可以选择“包含在组合价”或“单独计价”。包含在组合价时搭售商品成交价为0，但其库存成本仍计入组合毛利。
- 达人商品固定价按SKU应用于独立销售、组合主商品和单独计价的搭售商品；包含在组合价的搭售商品仍为0元且不建立价格关联。
- 配件商品作为搭售明细时自动视为包装耗材，强制包含在组合价；配件耗材总成本按各配件当前平均成本乘以对应搭售数量后求和。
- 每个组合提交时比较“配件耗材总成本”和“主商品包装费/件 × 主商品数量”；配件耗材成本更高时必须提示差额并禁止提交，草稿仍可保存。
- 配件耗材仍按自身SKU扣减库存，但组合毛利只按手填包装费和实际配件耗材成本中的较高值计费，不能重复扣除配件成本。
- 包装费、物流费默认由主商品承担，搭售商品默认不重复带入费用；必要时可在搭售行手工填写鉴定等费用。
- 主商品和搭售商品按各自SKU分别冻结、扣减和记录库存流水，流水保留相同的销售组合编号。
- 同一搭售SKU允许出现在不同销售组合中，但同一个销售组合内不能重复。
- 历史单据保存商品类型、规格类型、销售角色和计价方式快照，后续修改商品档案不改变原销售含义。

### 9.3 供应商退货单

单据头：

- 退供日期
- 供应商
- 退供原因
- 原采购单号，必选；只能选择该供应商已入账、未红冲且仍有可退数量的采购入库单
- 备注

明细由原采购单带出，至少包含SKU、商品名称、原采购单价、剩余可退数量、退供数量、实际退货单价、退货金额、当前平均成本和退供资产金额。供应商结算金额按“实际退货单价 × 退供数量”计算；库存资产减少金额按退供时当前平均成本计算，两者分别记录。

同一采购明细累计处于待审核或已入账状态的供应商退货数量不得超过原采购数量；保存和提交时均由后端校验，提交时锁定原采购单防止并发超额退货。原采购单存在待审核或已入账供应商退货时，禁止整单红冲。

提交后冻结对应可售库存，审核通过后扣减可售库存（同时扣减账面总库存）。

### 9.4 消费者退货登记单

单据头：

- 退货日期
- 销售渠道
- 平台订单号
- 退货原因
- 备注

明细包含SKU、商品名称和退货数量。

审核通过后增加售后待检数量，不增加可用库存。

- 消费者退货可选择关联一张已入账且未红冲的原销售单，也可在无法确认原单时手工登记。
- 已关联原销售单时，退货明细必须来自原销售明细；同一销售明细累计已退和待审退货数量不得超过原出库数量，并使用原销售明细保存的成本快照作为后续良品退回成本。
- 未关联原销售单时，必须填写销售渠道、退货商品、数量和实际退款单价；实际退款总额默认按各明细“实际退款单价 × 数量”自动汇总，允许人工改写以处理优惠、补偿等差异退款；系统使用登记时的库存平均成本作为待检成本快照，并将单据标记为“需复核”。
- 原销售存在销售组合时，选择原销售单后必须按原组合顺序带出主商品和全部尚可退的搭售商品，并显示原销售数量、剩余可退数量和原组合角色。修改主商品退货数量时，前端按原组合比例同步建议搭售数量；用户仍可按实际收到情况单独修改或删除某个搭售SKU，实现部分退货。
- 未关联原销售单时，系统不自动复制某一张历史销售单的整套组合；商品下拉框允许选择商品档案中的任意启用商品。整套退货仍建议选择原销售单，以便还原准确的组合和数量比例。
- 客户退货单单独记录实际退款总额；与所选原销售明细金额不一致时标记为“需复核”。退款金额按原成交金额比例分摊到退货明细，只有零价搭售商品退回时分配到该搭售明细。
- 未关联原销售单时，达人/主播为可选项。选择达人时，系统按“达人 + 所选商品”读取当前正式固定价，已定价商品逐行显示系统应退单价并自动带入实际退款单价；达人已绑定且包含在组合价中的搭售散件，系统应退单价和实际退款单价均锁定为0，并提示“已包含在主商品退款价中”，只参与退货库存处理，不重复增加退款金额；其他未建立正式固定价的商品允许选择，由制单员填写实际退款单价。未选择达人时，可选择任意启用商品并手工填写实际退款单价，系统应退单价显示为空。未关联原销售单的客户退货统一标记为“需复核”。关联原销售单时始终以原单明细价格快照为准。

### 9.5 退货质检处理单

单据头必须关联一张已入账且未红冲的消费者退货登记单。商品明细由原退货单自动带入，禁止手工选择无关商品。

明细表：

- SKU
- 商品名称
- 当前待检数量
- 良品数量
- 次品数量
- 处理说明

必须满足：

```text
良品数量 + 次品数量 <= 当前可处理待检数量
```

允许对同一客户退货明细分批质检；系统按原退货明细统计已保存、待审和已入账的质检数量，剩余待检数量不得小于本次处理数量。

提交后立即冻结本单使用的待检数量，避免多张待审质检单重复处理同一批退货。

审核通过后：

- 良品从售后待检转入可售库存，账面总库存不变。
- 次品增加次品库存。
- 两者共同减少售后待检数量。

### 9.6 库存盘点调整单

明细表：

- SKU
- 商品名称
- 系统可售库存
- 实盘库存
- 差异数量
- 盘盈核定单位成本
- 调整原因

```text
差异数量 = 实盘可售库存 - 系统可售库存
```

盘盈规则：

- 盘盈必须填写核定单位成本。
- 盘盈审核通过后，按核定单位成本增加库存资产并重新计算移动平均成本。

盘亏规则：

- 盘亏按当前平均成本减少库存资产，平均成本不变。
- 盘亏单提交时冻结差异数量。
- 盘亏不得使可用库存或可售库存变为负数。

审批规则：

- 提交后由审核员初审，初审通过后转交管理员复核。
- 管理员终审盘点单时，可以修改盘盈明细的核定单位成本；制单人和初审审核员不能在审批环节修改。
- 管理员修改后的核定成本与终审通过在同一事务中保存并入账，同时记录修改前后成本的审计事件。
- 管理员复核通过前不改变可售库存；复核通过时在同一事务中更新库存并写入流水。
- 初审和复核前都要重新校验盘点时的可售库存快照；库存已变化时禁止通过，需驳回后重新盘点。
- 库存调整单的红冲同样需要审核员和管理员双级审批。

### 9.7 手工组装单

手工组装单用于消耗散件并产出成品。制单员可以选择已有成品，也可以在组装单内直接建立一个新的成品档案。

新建成品规则：

- 必须填写唯一SKU、商品名称和规格类型，可填写分类、单位、库存预警值和一张成品参考图。
- 后端强制将新档案保存为“成品商品”，不能借此创建散件商品或绕过其他商品管理权限。
- 保存组装草稿时，在同一个数据库事务中创建成品档案、初始化零库存并关联组装单产出行。
- SKU重复、组装单校验失败或单据保存失败时，成品档案和组装单整体回滚，不保留半成品数据。
- 新成品创建时库存为0；组装单提交后冻结散件，审核通过后扣减散件并增加成品库存。
- 已创建的新成品进入普通商品档案，后续组装可以直接选择复用。

### 9.8 库存成本调价单

库存成本调价单由制单员发起，用于修正有可售库存SKU的移动平均成本，不改变库存数量。

库存盘点页面另提供管理员“仅调成本”快捷入口：管理员在实盘数量与系统数量一致时修改成本并填写原因，保存后直接生成已入账的成本调价单、更新平均成本并写入数量变化为0的库存流水，不经过审批。该入口不向制单员或审核员开放，且不能与同一次盘盈/盘亏混合保存。库存盘点记录列表同时展示盘点调整和成本调整记录；成本调整记录需显示库存金额变化，并在详情中展示调整前、调整后成本及审批方式。

- 明细记录当前库存数量、当前平均成本和调整后平均成本，必须填写调价原因。
- 保存草稿时读取并保存当前平均成本快照；草稿只能由制单人本人编辑或删除。
- 提交后先由审核员初审，再由管理员复核；管理员复核通过时才更新库存平均成本并写入一条数量变化为0的库存流水。
- 最终复核前再次校验平均成本快照；若成本已变化，必须驳回后由制单员重新编辑。
- 调整前库存金额 = 当前库存数量 × 当前平均成本。
- 调整后库存金额 = 最终复核时库存数量 × 调整后平均成本。
- 库存金额变化 = 最终复核时库存数量 ×（调整后平均成本 - 当前平均成本）。
- 调价单处于待审核或待管理员复核期间，同一SKU的采购入库单允许保存草稿，但禁止提交或入账。
- 同一SKU已有待审核采购入库单时，调价单禁止提交；其他SKU不受影响。

## 10. 审批中心

审批中心包含：

- 待审核
- 已审核

列表字段：

- 单号
- 单据类型
- 制单员
- 供应商或销售渠道
- SKU种类数
- 总件数
- 总金额
- 毛利风险
- 提交时间
- 当前状态

审核员打开单据后查看完整只读明细表，可以填写审核意见并执行通过或驳回。库存调整单和库存成本调价单初审通过后转交管理员复核，不立即入账。

最终审核通过时必须在一个数据库事务中完成：

1. 校验单据当前状态。
2. 再次校验库存与人员隔离规则。
3. 写入审批记录。
4. 写入库存流水。
5. 更新库存汇总和平均成本。
6. 更新单据状态为已入账。

任一步骤失败，全部回滚。

## 11. 库存台账

库存台账为只读页面，按SKU展示：

查询区支持按 SKU/商品名称、商品类型和预警状态组合筛选，筛选条件在后端分页查询中生效。

- SKU
- 商品名称
- 商品分类
- 账面总库存
- 可售库存
- 待审冻结
- 当前可用库存
- 售后待检
- 次品库存
- 可售平均成本
- 可售库存资产
- 售后待检成本金额
- 次品成本金额
- 库存总资产
- 库存预警状态
- 最近变动时间

```text
可售库存资产 = 可售库存 × 可售平均成本

库存总资产 = 可售库存资产 + 售后待检成本金额 + 次品成本金额
```

售后待检和次品按照消费者退货携带的成本快照累计成本金额。第一阶段不计提次品减值。

点击SKU可以查看完整库存流水，包括来源单号、业务类型、变动前数量、变动数量、变动后数量、成本和操作时间。

## 13. 毛利试算

- 实时计算单件毛利、毛利率、保本售价和佣金上限。
- 亏损时红色预警。

试算台和销售出库必须调用同一套后端计算服务。

## 17. 第一阶段验收标准

### 17.1 权限

- 直播人员不能看到珠宝ERP菜单。
- ERP人员不能因为ERP角色获得直播业务权限。
- 珠宝ERP菜单、前端组件和接口权限不使用 `live` 命名空间。
- 制单员不能进入审批操作。
- 审核员不能创建业务单据。
- 非ERP管理员不能管理ERP人员、商品和供应商。

### 17.2 审批

- 制单人不能审核自己的单据。
- 普通单据只需一次审核；库存调整单和库存成本调价单必须由审核员初审、管理员复核，两次通过后才改变库存或平均成本。
- 调价审批期间，同一SKU的采购入库不能提交或入账；不同SKU仍可正常采购。
- 驳回、撤回能够正确释放冻结库存。
- 重复点击审批不会重复入账。
- 撤回后单据回到草稿，并保留撤回事件记录。

### 17.3 库存

- 所有库存变化都能追溯到单据和库存流水。
- 可用库存不能小于零。
- 同时提交多张出库或退供单时不会超卖。
- 同时提交盘亏单和出库单时不会超卖。
- 同时提交多张质检处理单时不会重复使用待检数量。
- 退货待检、良品和次品数量转换正确。
- 已关联原销售单的累计退货数量不会超过原销售数量；未关联退货能够正常进入待检并明确标记为需复核。
- 盘点调整保留调整前后数量和原因。
- 红冲不能造成负库存、重复红冲或错误成本。

### 17.4 成本与毛利

- 采购入库后的移动平均成本计算正确。
- 盘盈按照核定成本重新计算平均成本，盘亏按当前平均成本扣减资产。
- 历史出库成本不受后续采购价格影响。
- 试算台与销售出库的毛利结果一致。
- 亏损销售单在制单和审核环节均有明确预警。
- 金额、成本和费率在前后端使用一致的精度和舍入规则。

### 17.5 数据

- 已入账单据不能直接修改或删除。
- 商品和供应商停用不影响历史数据展示。
- 所有关键操作都记录真实登录账号和时间。
- 商品、供应商、库存和单据导出结果与页面数据一致。
